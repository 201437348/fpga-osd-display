# 行缓存水平推拉转场设计

日期：2026-09-09

## 目标与选择依据

实现符合赛题“利用行缓存实现左右滑动切换”的图片转场：新图从右侧平滑推入，旧图向左
退出。移除暖白/金色滤镜、斜向扫光和闪白，不再尝试已经在开发板上多次花屏的全屏双帧
Alpha 回读。

当前稳定版本每个输出像素只从一个 SDRAM 帧缓冲读取一次。新设计保持这一基本吞吐量：
普通滑动区域每行共读取 640 个像素；只有交界处启用柔边时额外读取最多 32 个像素，因此
最坏为每行 672 次读取，而不是全屏 Alpha 混合所需的 1280 次读取。

## 视觉行为

- 首张图片直接显示，不播放转场。
- 新图片提交后，在下一个完整视频帧边界开始转场。
- 新图从屏幕右侧进入，旧图同步向左退出，画面尺寸和纵向位置不变。
- 转场使用 28 个推进步骤，在 60 Hz 下约为 0.47 秒。
- 水平位置采用固定 smoothstep 表：
  `0,2,9,20,35,54,76,100,127,156,187,219,252,286,320,354,388,421,453,484,513,540,564,586,605,620,631,638,640`。
- 当分界线距离左右边缘均不少于 16 像素时，使用 32 像素柔边。柔边从旧图线性过渡到
  新图，不叠加颜色、亮度、阴影或装饰线。起始和结束 16 像素范围内关闭柔边，保证端点
  精确显示完整旧图或新图。
- OSD 继续在转场之后合成，标题、滚动字幕和状态栏固定不动。

## 控制器

`video_transition_controller` 在视频时钟域管理帧级状态，输出：

- `active_buffer_index[1:0]`：非转场时读取的稳定画面；
- `slide_old_buffer_index[1:0]` 和 `slide_new_buffer_index[1:0]`：一次转场期间锁定的源、目标；
- `slide_active` 与 `transition_busy`：转场有效和播放加载互锁；
- `slide_position[9:0]`：按固定表从 0 单调增加到 640。

控制器只在 `video_read_req` 的新帧边沿更新步骤。开始时锁定当前活动缓冲区和最新已提交
缓冲区；最后一步到达 640 时，把 `active_buffer_index` 切换为目标缓冲区并结束转场。
转场期间若出现新的提交，只保留最新目标，待当前互锁释放后再处理，不改变正在使用的两个
缓冲区索引。

## 单 FIFO 行调度器

生产路径保留一个异步输出 FIFO。新的行调度器替代只能连续读取整帧的
`frame_fifo_read` 调度逻辑，但不增加第二个全帧读 FIFO。

对于第 `y` 行和滑动位置 `p`，无柔边时按输出顺序发出两个连续地址段：

1. 旧图段长度 `640-p`，起始地址为 `old_base + y*640 + p`；
2. 新图段长度 `p`，起始地址为 `new_base + y*640`。

两个段的返回数据依次写入同一个输出 FIFO，所以视频端仍连续读出恰好 640 个像素。普通
显示等价于 `p=0` 且只读取活动缓冲区；转场完成后等价于读取完整新图。

在完整 32 像素柔边阶段，令 `b=640-p`。旧图读取 `b+16` 个像素，起始横坐标为
`p-16`；其中前 `b-16` 个直接输出，最后 32 个作为重叠段。新图读取 `p+16` 个像素，
起始横坐标为 0；其中前 32 个作为重叠段，剩余 `p-16` 个直接输出。调度顺序为旧图
非重叠段、旧图重叠段、新图重叠段、新图非重叠段。

旧图的 32 个重叠像素暂存在小型 overlap cache；新图对应像素返回时，按位置系数完成
RGB Alpha 混合后写入输出 FIFO。两个源在边界两侧各多延伸 16 像素，因此源图内部坐标
连续，没有重复、跳跃或越界。旧、新重叠读取各 32 像素，但在最终输出中只产生 32 个
混合像素，所以总读取量为 672、每行输出仍严格为 640 个像素。

所有 SDRAM 读命令仍串行使用同一个 `App_rd_en/App_rd_addr` 接口。一次地址段的返回数据
全部收到前不切换路由状态；使用实际 `Sdr_rd_en` 计数确认返回，而不是只按固定延时推断。
图像加载完成后才启动转场，因此转场期间不存在新的整帧写入竞争。

## 跨时钟域与请求锁存

视频域的缓冲区索引、`slide_active` 和 `slide_position` 必须在每帧请求对应的内存事务开始
前原子锁存。内存域在同步后的 `read_req` 首次变低时锁存最终元数据，然后才开始本帧读取，
避免复现旧双读方案中“请求先到、模式和索引后到”的首帧竞态。

输出 FIFO 每个视频帧开始时清空。行调度器按水位提前读取，任何时刻只维护一个最终像素
流；不恢复旧方案的 `read_data_old`、第二 FIFO 或返回数据双路路由。

## 边界与故障处理

- `slide_position=0` 时逐像素等同完整旧图，`slide_position=640` 时逐像素等同完整新图。
- `slide_position<16` 或 `slide_position>624` 时不启用柔边，避免负地址、越界地址和不足
  32 像素的重叠段。
- 每行发出的最终 FIFO 写入数必须等于 640；每帧必须等于 307200。
- 若下一视频帧请求到达时上一帧的 307200 个输出像素尚未排入 FIFO，锁存调度超时诊断并
  停止转场，继续显示旧活动缓冲区，不切换到可能不完整的新画面。
- TF 拔出、存储错误和加载超时继续使用现有媒体故障优先级，不由转场模块改写。

## 验证

控制器仿真覆盖首图直通、28 步位置表、索引锁定、终点切换和忙信号释放。行调度器使用小
尺寸参数化画面验证每行旧/新地址段、输出顺序、柔边恰好 32 像素、端点无混色、返回延迟
变化时路由不串线，以及每行/每帧输出计数。

集成仿真使用不同的旧图、新图像素模式，验证左侧旧图平移、右侧新图进入和柔边 RGB
系数；同时确认 OSD 不移动。真实顶层必须只实例化一个读 FIFO，并通过 TD 综合、布局布线
和 JTAG。板测至少执行十次手动转场、多轮自动播放、音频连续性、OSD 稳定性和一次 TF
拔插恢复；出现花屏、黑带、行错位、HDMI 失锁或加载超时即判定失败，不写配置 Flash。

## 范围

本轮只修改转场控制、单 FIFO 行读取调度、必要的顶层接口和对应测试。BMP/WAV 格式、
FAT32、图片写入、垂直翻转、音频、HDMI 时序、OSD 内容、按键定义、自动播放间隔、
125 MHz SDRAM PLL 和刷新周期保持不变。
