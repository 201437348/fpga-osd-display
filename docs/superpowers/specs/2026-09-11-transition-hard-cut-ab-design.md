# Transition Hard-Cut A/B Diagnostic Design

## Goal

Determine whether the fixed colored column at physical screen `x=0` is
generated by transition feather blending or by another part of the video
path.

## Design

Add a compile-time `FEATHER_ENABLE` parameter to `frame_slide_fifo_read` and
pass it through `frame_read_write`.  When disabled, the scheduler retains the
same horizontal slide position, old/new buffer selection, frame dimensions,
FIFO pipeline, and SDRAM backpressure behavior, but uses the existing
non-feathered old-direct/new-direct phases for every transition position.

The production top explicitly selects `FEATHER_ENABLE=0` for this diagnostic
bitstream.  Module defaults remain enabled so existing unit tests and other
instantiations preserve their current behavior unless they deliberately opt
into the diagnostic.

## Verification

Run the 640-by-2 full-line test twice: once with feathering enabled and once
with it disabled.  Both modes must produce exactly 640 ordered pixels per row
at positions `0`, `2`, `16`, `320`, `624`, `638`, and `640`, with the disabled
mode checked against a hard old/new boundary.  Re-run the focused scheduler,
transition-controller, underflow, line-boundary, and top-elaboration tests.
Then build `syn_1`, `phy_1` seed 2, and the bitstream.  Board acceptance is a
single observation: whether the fixed left-edge colored line remains during
motion.

## Interpretation

- Line disappears: feather composition is implicated.
- Line remains essentially unchanged: feather composition is excluded; the
  next diagnostic must identify whether `x=0` corruption exists before or
  after the HDMI AXIS boundary.
