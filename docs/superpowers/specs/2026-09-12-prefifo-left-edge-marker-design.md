# Pre-FIFO Left-Edge Marker Diagnostic Design

## Goal

Determine whether the fixed left-edge color is already present in the slide
scheduler output or is introduced while reading the asynchronous display FIFO.

## Design

Add default-disabled `READ_FIFO_MARKER_ENABLE` and configurable
`READ_FIFO_MARKER_WIDTH` parameters to
`frame_read_write`.  Between `frame_slide_fifo_read` and the asynchronous read
FIFO, track the scheduler's accepted output position within each row.  When
the diagnostic is enabled, replace x=0 through
`READ_FIFO_MARKER_WIDTH-1` with `32'hFFFFFF00` and pass later pixels unchanged.
Reset the position with the FIFO clear pulse and wrap at `FRAME_WIDTH-1`.

Enable this marker only in the production top for the diagnostic build.  Keep
the final AXIS marker disabled, normal feathering enabled, OSD connected, and
the registered-output FIFO timing fix in place.

## Verification

Use a 68-by-2 focused test with 136 distinct scheduler output words.  Require
white for x=0..63 and the original word for x=64..67 on both rows.  Re-run the
underflow, transition, full-line, FIFO/video-delay, OSD, AXIS, and top-level
regressions.

## Board Interpretation

- A stable white band reaches the physical left edge and the old color line is
  gone: the offending x=0 value is generated by the slide scheduler.
- An image-colored line remains left of or inside the white band, or the white
  band does not begin at the physical edge: the asynchronous FIFO/read timing
  introduces or shifts the offending pixel.
- A line that was at x=16 moves to the new x=64 marker boundary: investigate
  the first unmasked scheduler word or a repeated boundary word.
- A line remains at its old physical position but is covered by the wider
  marker: the scheduler produces a multi-pixel corrupt region near line start.

## Diagnostic Results

The 16-pixel marker left a color line visible to its right. The 64-pixel
marker remained clean and removed the color line completely. The 32-pixel
marker also removed it. Both the 24-pixel and 26-pixel markers left a small
color edge visible, while the 31-pixel marker removed it, bounding the last
visible edge to x=26..30. Because every test so far used a prefix marker, it
may also have hidden earlier artifacts. Add a marker start parameter and cover
only x=26..30 next, leaving x=0..25 and x=31 onward unchanged.
