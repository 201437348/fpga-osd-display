# 图片滑入转场设计

日期：2026-09-08

## 目标

在已经通过板测的 BMP 轮播、HDMI 音频、OSD 字幕和 TF 热插拔系统中，增加一个
可辨识且资源受控的图片切换转场，满足赛题“图片切换与转场特效”扩展项。

## 方案

采用右侧向左的遮罩滑入。图片管理器仍然在后台完成整帧写入，并在提交点切换
显示缓冲区；`video_osd_overlay` 通过同步后的 `current_image_index` 变化识别
提交的新图，将该变化挂起到下一次帧边界后，在随后的 20 个视频帧内逐步扩大
可见区域。每帧扩大 32 像素，
因此约 0.33 秒后整幅新图可见。字幕带、顶部标题栏和底部状态栏不参与遮罩，
始终保持稳定可读。

该方案不需要同时读取新旧两帧，不引入 SDRAM 读口、行缓存、BRAM、跨时钟握手
或新的顶层端口；未揭幕的图像区域输出黑色。复位时不触发转场，首图仍按现有
路径直接显示。

## 时序与异常

- `current_image_index` 变化是唯一的转场触发条件；变化先被挂起并在下一次
  `vs` 上升沿开始转场。图片加载失败、TF 拔出、回插恢复和音频状态变化不会
  触发或重置转场。
- 触发后的揭幕计数只在 `vs` 上升沿递增，保证每个完整视频帧使用一致的边界。
- 计数范围为 0..20；第 0 帧显示右侧 32 像素，第 19 帧显示整幅图，随后回到
  透明直通模式。
- 若新图在转场期间再次提交，计数立即从 0 重新开始，以最新提交的图像为准。
- 转场仅作用于有效图像区 `y=24..431`；字幕区 `y=432..455`、状态栏
  `y=456..479` 和顶栏不受影响。

## 验证

Icarus 单元测试检查：

1. 图像提交变化后，图像区先输出黑色遮罩，右侧已揭幕像素保持原 RGB；
2. 每个 `vs` 边界最多推进一个转场帧，20 帧后恢复完整图像；
3. 顶栏、字幕带、状态栏和普通无转场图像保持已有颜色与优先级；
4. 转场期间改变 `storage_ready`、加载状态或显示测试图案不会重置计数。

通过仿真后，使用 TD GUI 的 `syn_1`、`phy_1` 与 JTAG 板测；确认基础播放、
音频、字幕和热插拔无退化后，再考虑更新配置 Flash。

## 非目标

本项不实现旧帧与新帧的 alpha 淡入淡出、不改变 BMP 格式限制、不修改 SDRAM
控制器、TF 读取器、音频 FIFO、PLL、视频时序或按键定义。
