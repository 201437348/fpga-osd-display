# 斜向交叉淡入淡出转场设计

日期：2026-09-08

## 目标

以用户选定的 C 方案替代已验证但视觉生硬的黑幕滑入。每次新图片完整写入
SDRAM 并提交后，旧图必须持续可见、缓慢淡出；新图必须同步淡入，并伴随一条
从左上至右下扫过画面的暖色斜向高光。整个过程不出现黑屏、旧图瞬间消失或
按帧闪烁。

## 视觉行为

- 首图、无转场、TF 拔出、回插恢复和彩条回退保持原有画面，不触发转场。
- 正常的 `KEY2` 或 `KEY4` 成功切图，在约 17 个输出帧内完成转场，时长约
  0.28 秒。
- 第 0 帧显示完整旧图；此后旧图按线性 alpha 系数淡出，新图以互补 alpha
  系数淡入；第 16 帧显示完整新图。
- 斜向高光只在图片区扫过，不覆盖顶栏、滚动字幕或状态栏。它是对交叉淡入
  淡出的装饰，不取代旧图和新图的同步混合。
- 现有音乐、顶部标题、滚动字幕、`IMAGE/LOAD/WAIT TF` 状态、按键和自动
  轮播语义保持不变。

## 关键限制与结论

现有设计在每个视频帧只从一个 SDRAM 读 FIFO 取像素，因此只能显示新图，
无法让旧图离场。两张 640x480、32-bit 帧仍完整保存在 `BUF0_ADDR` 与
`BUF1_ADDR`；SDRAM 用户接口工作在 125 MHz，而视频有效像素输出为 25 MHz，
转场期间双帧读取平均约需 1.18 Gbit/s，低于理论 4 Gbit/s 接口上限。

因此采用真正的双帧读取，而不是逐帧新旧图切换的伪淡入。伪淡入会在 60 Hz
下产生闪烁，不能作为比赛现场效果。

## 架构

### 视频域转场控制

新增 `video_transition_controller`，运行在 `video_clk` 域。它同步图片管理器
已提交的缓冲区索引，并保留 `active_buffer_index`、`old_buffer_index` 与
`new_buffer_index`。

检测到新提交缓冲区后，控制器等待下一次 `video_read_req` 帧请求：锁定旧/新
缓冲区、置位 `dual_read_active`、从 alpha 步进 0 开始。每次随后的帧请求使
步进加一；步进到 16 后，单帧读路径切换到新缓冲区并清除 `dual_read_active`。
复位和首图不会触发。

转场活动状态同步回 `sd_card_clk` 域，并与 `manager_idle` 相与后送入按键/自动
轮播控制。这样，在旧帧仍被读取的约 0.28 秒内，新的人工或自动加载请求不会
开始覆盖旧缓冲区；该期间的按键与现有“加载忙时忽略”行为一致。

### SDRAM 双帧读取

`frame_read_write` 保留现有写路径和单帧读行为。转场时，它通过新
`frame_dual_fifo_read` 在同一 SDRAM 用户端口交替发送旧帧和新帧的 256-word
突发读请求；每个突发完整返回后才切换目标 FIFO，避免依赖未验证的按周期数据
标签假设。

现有新图读 FIFO 继续输出 `read_data_new`；新增同规格异步 FIFO 输出
`read_data_old`。双帧模式下每个有效像素时钟同时从两个 FIFO 读取一个 RGB
像素。单帧模式只填充和使用新图 FIFO，旧 FIFO 内容不参与输出。两个 FIFO
都在每次帧请求开始时独立清空，避免跨帧残留。

### 视频混合与 OSD

现有 `video_delay` 对新图和旧图各实例化一次，确保两个 RGB 流与 HS/VS/DE
严格相同延迟。新增 `video_transition_blender` 在 OSD 之前合成像素：

```text
rgb = old_rgb * (16 - alpha) / 16 + new_rgb * alpha / 16
```

混合只在 `dual_read_active` 时启用；非活动时直接透传新图。混合器以当前像素
坐标生成一条有限宽度的斜向暖色高光，且仅在图片区显示。乘法在 25 MHz 域中
使用少量 DSP 或 LUT 逻辑实现，以 TD 资源报告为准。

`video_osd_overlay` 删除黑色滑入遮罩和其内部转场状态，只保留已板测通过的
标题、状态栏和字幕功能。这样 OSD 始终位于转场画面之上。

## 时序与异常策略

- 双帧模式的缓冲区索引和模式与 `video_read_req` 一同跨到 SDRAM 域，并在
  读请求确认后锁定至该视频帧读取完成。
- 一次突发完整接收后才切换旧/新 FIFO 写入目标；读 FIFO 水位不足以容纳整个
  突发时暂停发起对应突发。
- 若 TF 在转场期间拔出，既有存储故障路径优先：管理器中止加载、保留已显示
  图片；视频侧让已开始的转场按当前 SDRAM 内容完成，再回到单帧保留画面。
- 若新图片提交发生在转场中，视频控制器放弃旧的 alpha 序列，在下一帧请求
  以当前稳定显示缓冲区和最新已提交缓冲区重新开始。正常图片加载时间远大于
  转场时长，但该规则确保行为明确。
- 任何 SDRAM/FIFO 欠读都不能将旧图替换为黑幕；沿用现有视频时序下的 FIFO
  数据路径，板测时必须特别观察是否存在条纹、闪烁或 HDMI 失锁。

## 文件边界

- 新增 `rtl/video/video_transition_controller.v`：视频域提交检测、缓冲区锁定、
  alpha 步进和转场忙状态。
- 新增 `rtl/video/video_transition_blender.v`：双 RGB 流 alpha 混合与斜向高光。
- 新增 `rtl/vendor/SD/frame_dual_fifo_read.v`：SDRAM 域双 FIFO 突发读调度。
- 修改 `rtl/vendor/SD/frame_read_write.v`：连接双读调度器和第二读 FIFO，同时
  保留写路径。
- 修改 `rtl/top/top.v`：接入控制器、两条延迟流、混合器和播放互锁。
- 修改 `rtl/video/video_osd_overlay.v`：移除黑幕滑入逻辑。
- 修改 `.al` 项目源清单和 `tests/top_compile_stubs.v`。
- 新增或扩展转场控制、混合器、双突发调度、OSD 和顶层语法测试。

## 验证门

1. Icarus 单元测试验证 alpha 端点、中间混合、高光区域、首图直通、双读突发
   地址与 FIFO 路由、单帧回退、转场忙互锁和现有 OSD 行为。
2. Icarus 顶层语法检查覆盖新增端口和项目源顺序。
3. 用户在 TD GUI 运行 `syn_1`、`phy_1`；记录资源与时序报告，不将既有负
   建立裕量表述为已收敛。
4. 用户 JTAG 板测：首图、单次和连续 `KEY2`、`KEY4` 轮播、音乐连续播放、
   字幕/状态稳定、快速/中等/长时间 TF 热插拔及回插恢复。
5. 全部通过后才更新配置 Flash。

## 非目标

本项不改变 BMP/WAV 格式、FAT32 读取、SDRAM 写路径、音频 FIFO、PLL、HDMI
时序、图片缩放、亮度对比度控制或音频可视化。斜向高光不做任意图像几何重采样；
它与真实双帧交叉淡入淡出结合，保证画面质量和实现风险处于可控范围。
