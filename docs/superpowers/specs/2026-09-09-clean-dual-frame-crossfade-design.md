# 纯双帧交叉淡化转场设计

日期：2026-09-09

## 目标

将已板测无花屏但视觉不合格的暖白遮罩转场，替换为用户选定的纯交叉淡化：旧图逐步
变透明，新图同时逐步显现。转场中不加入白色或黄色遮罩、不改变色温、不绘制斜线，
也不平移、缩放图片。总时长维持在当前观感合适的约 `0.53 秒`。

## 已确认取舍

真正的交叉淡化要求每个输出像素同时取得旧图和新图。整帧交替只能形成可见闪烁；
单帧淡到白或淡到黑虽然稳定，但不符合本次视觉选择。因此重新启用双帧 SDRAM 读取，
接受它相对单帧路径更高的带宽和上板风险，同时保留当前单帧实现的代码历史作为回退依据。

此前双帧版本即使通过理想化仿真，上板仍出现转场花屏。本轮不能只恢复旧代码：需要明确
锁定新旧缓冲区角色、缩短两路 FIFO 的轮询间隔、增加读缓冲深度，并扩展仿真覆盖 FIFO
返回路由和像素对齐。若上板仍花屏，应将结果归因于双帧持续读或既有 SDRAM 负时序裕量，
而不是再叠加装饰效果掩盖。

## 视觉行为

- 首图直接显示，不播放转场。
- 新图片完整写入并提交后，在下一个视频帧请求开始交叉淡化。
- 交叉淡化占用 32 个 60 Hz 输出帧，约 `0.53 秒`。
- 旧图权重从 64 单调下降，新图权重从 0 单调上升，两者始终互补。
- 使用 32 级缓入缓出 alpha 表：
  `0,1,2,3,4,5,7,9,11,13,15,17,20,23,26,29,32,35,38,41,44,47,49,51,53,55,57,59,60,61,62,63`。
  下一帧直接进入权重 64 的新图，端点跳变量仅为 1。
- RGB 每通道执行
  `((old * (64 - alpha)) + (new * alpha)) >> 6`；alpha 为 0 时精确输出旧图，
  非双读状态精确输出当前图。
- OSD、滚动字幕和音频状态继续在混色之后合成，不随图片变透明。

## 架构

### 视频域控制器

`video_transition_controller` 恢复并简化为双帧控制器。它维护：

- `active_buffer_index`：非转场时的当前显示缓冲区；
- `old_buffer_index`：本次转场开始时锁定的当前图；
- `new_buffer_index`：本次转场开始时锁定的已提交目标图；
- `dual_read_active`、`transition_busy` 和 `alpha_step[6:0]`。

检测到新提交后只设置 pending。在下一个 `video_read_req` 上升沿，控制器锁定旧、新索引，
从 alpha 0 启动。之后每个帧请求推进一次查表值；显示过 alpha 63 的帧后，在下一个帧
请求把 `active_buffer_index` 更新为目标图并退出双读。转场忙信号继续同步到 TF 时钟域，
阻止图片管理器在旧图仍被使用时覆盖其缓冲区。

### SDRAM 双读和 FIFO

`frame_read_write` 保持写路径不变，显示读取改用 `frame_dual_fifo_read` 和两个独立异步
FIFO。非转场时只填充 new/current FIFO；转场时：

- new FIFO 的地址固定来自 `new_buffer_index`，不得误接仍指向旧图的 active 索引；
- old FIFO 的地址固定来自 `old_buffer_index`；
- `route_old_fifo` 从发出一批地址前开始锁定，直到该批全部真实 `Sdr_rd_en` 返回完成；
- 每批读取 64 个 32-bit 字，在两个 FIFO 之间按水位优先调度，水位相同时交替；
- 两个读 FIFO 深度由 512 增至 1024 字，减少 SDRAM 仲裁和刷新造成的瞬时欠读风险；
- 每个视频帧请求同时清空两路 FIFO，随后从各自帧首地址重新顺序填充。

`video_read_req` 会先于控制器的新双读模式约一个像素时钟到达存储域。调度器因此在 ACK
状态中持续采样模式、索引和长度，并在同步后的请求首次变低时再执行一次最终原子锁存，
之后才开始发读命令。这样，模式和目标索引不会被错误地归到下一帧，第一帧 alpha 0 也
能取得有效 old FIFO 数据，而不是读取未填充的旧帧端口。

两个 FIFO 在有效像素期由同一个 `read_en` 同拍弹出。顶层用两套相同 `video_delay`
取得对齐的 24-bit RGB，再进入混色器。任何新旧索引、模式或帧长度只在请求确认阶段
锁存，在整帧读取结束前不允许变化。

### 纯混色器

`video_transition_blender` 删除坐标计数、暖白插值、金色插值和斜线逻辑，只保留两路
RGB 互补加权。组合乘加使用足够位宽容纳 `255 * 64`，并为 alpha 0、非转场状态提供
精确旁路。这样转场模块不再引入任何额外颜色语义。

## 异常与边界

- 转场忙时继续禁止新的手动或自动加载请求，避免旧缓冲区被覆盖。
- TF 拔出沿用现有加载恢复策略；已经完整提交的两帧仍可完成转场。
- 非转场帧仍只读取一张图，音频、FAT32、BMP/WAV 加载、SDRAM 写入、PLL、HDMI
  时序、按键和 OSD 内容均不修改。
- 不在 RTL 中用黑块、白块或上一像素掩盖 FIFO 欠读。上板若出现方块或撕裂，应保留
  现象用于定位双读带宽或 SDRAM 时序问题。

## 验证

Icarus 仿真必须覆盖：首图直通、pending 到帧边界启动、32 帧 alpha 序列、旧新索引
锁定、完成后切换 active 索引、端点和中点 RGB、非转场精确旁路、单读与双读地址、
延迟及间断 `Sdr_rd_en` 返回、返回期间路由不变、FIFO 水位偏斜时优先补低水位、以及
请求确认后晚到的双读模式/索引仍被当前事务锁存、顶层两路数据和 OSD 层级连接。

TD 构建后只使用 JTAG。板测至少执行十次 `KEY2`、多轮 `KEY4`、一次 TF 拔插恢复，
并同时观察音乐和 OSD。验收标准是约半秒内旧图连续消失且新图连续出现，没有白闪、
黄条、矩形花屏、撕裂、黑帧或 HDMI 失锁。通过前不写配置 Flash。
