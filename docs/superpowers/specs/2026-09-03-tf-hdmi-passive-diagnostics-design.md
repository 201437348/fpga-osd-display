# TF-HDMI 六位数码管被动诊断设计

日期：2026-09-03

## 背景与结论

工作副本已经使用 TD 6.2.1 完成原样综合、布局布线和 JTAG 上板验证。新生成的 bit 与官方 2026-06-05 版本表现一致：数码管状态为 `2 -> 4 -> 1`，HDMI 有信号但画面全黑，`KEY2` 和 `KEY4` 没有可见效果。

最终时序报告为 `SWNS=-6.565ns`、`STNS=-297.430ns`，最差的 32 条路径位于 SDRAM `DQ[31:0]` 数据口。工具同时报告 SDRAM 位置约束未采用以及 SDRAM 时钟使用本地布线。当前证据说明问题位于首图加载、SDRAM 写入完成、跨时钟同步、显示提交或 SDRAM 读回链路，但尚不能只凭时序报告认定唯一根因。

## 目标

在不改变原有 TF、SDRAM、HDMI、按键和超时行为的前提下，把首图加载链路中的关键事件锁存并显示在六位数码管上，确定黑屏时系统停在哪个检查点。

本轮只做诊断，不修复故障，不开发 OSD，不修改 SDRAM 约束，也不把 1 秒加载超时延长到 10 秒。

## 可见格式

六位数码管从左到右显示：

```text
S C L R W X
```

各位含义如下：

| 位 | 范围 | 含义 |
| --- | --- | --- |
| `S` | `0` 到 `4` | 当前 TF/BMP 状态机状态，沿用官方 `state_code` |
| `C` | `0` 到 `4` | 扫描到的合格 BMP 图片数量 |
| `L` | `0` 或 `1` | 是否启动过首图加载 |
| `R` | `0` 或 `1` | 是否观察到 BMP 源数据发送完成 |
| `W` | `0` 或 `1` | 是否观察到 SDRAM 整帧写入完成事件 |
| `X` | `0`、`1` 或 `E` | `0` 表示尚无结果，`1` 表示显示提交成功，`E` 表示加载超时 |

例如，最终显示 `14110E` 表示状态机已经回到空闲、找到 4 张图、启动过加载、源数据已经发送完成、没有观察到 SDRAM 整帧写入完成，最后因超时退出。

## HDL 边界

### `sd_card_bmp`

增加一个只读诊断输出总线，输出图片数量和五个锁存事件：

- 首图加载启动；
- `bmp_ready` 在加载期间出现；
- 同步后的 `write_finish_pulse` 在加载期间出现；
- `display_valid` 被置位；
- `load_abort` 因超时触发。

事件锁存器在 `rst` 有效时清零，此后保持到下一次 `KEY1` 用户逻辑复位。超时位一旦置位即保持；结果位显示时以超时 `E` 优先于提交成功 `1`。

诊断信号只能旁路观察现有条件，不参与原状态机的分支、握手、地址、数据或时钟控制。

### `top`

接收诊断总线，为六个十六进制数码管位分别实例化既有的 `seg_decoder`，并继续复用既有 `seg_scan`。不增加顶层引脚，不修改 ADC/SDC 约束。

物理位顺序按现有扫描器的 `seg_data_5` 到 `seg_data_0` 映射为左到右 `S C L R W X`。若板卡实际丝印方向与该顺序相反，只调整顶层显示连线，不改变诊断事件本身。

## 数据流

```text
TF/BMP 状态与事件
        |
        v
sd_card_bmp 内部粘滞锁存器
        |
        v
顶层六个 seg_decoder
        |
        v
既有 seg_scan -> 六位数码管
```

诊断路径是单向旁路，不能反向影响图片加载或 HDMI 视频数据。

## 构建与测试

1. 修改前保留当前原样构建报告和 bit，作为六月黑屏基线。
2. 对诊断版重新运行 `syn_1`，检查无错误且没有新增未驱动、多驱动或位宽警告。
3. 重新运行 `phy_1` 并记录时序结果。由于原工程已有严重 SDRAM 时序违例，诊断版不能因为成功生成 bit 就被判为时序通过。
4. 只用 JTAG 临时下载诊断 bit，不写配置 Flash。
5. 保持同一块板卡、同一张 TF 卡、四张官方 BMP、HDMI 线和 `SW6` 状态不变。
6. 上电后等待状态稳定，记录六位完整字符；再按一次 `KEY1`，确认锁存状态清零后重新形成相同结果。
7. 本轮不以 `KEY2`、`KEY4` 是否切图作为主要判据，因为 `display_valid=0` 时原逻辑本来就不会提交下一张图片。

## 判读规则

| 稳定结果特征 | 结论 | 下一步 |
| --- | --- | --- |
| `L=0` | 首图加载请求未启动 | 检查扫描完成、图片计数与启动条件 |
| `L=1, R=0, W=0, X=E` | BMP 数据源未正常结束 | 检查 BMP 扇区读取、写 FIFO 请求与 1 秒超时 |
| `L=1, R=1, W=0, X=E` | 源数据结束但未收到整帧写完成 | 优先检查写入长度、写 FIFO、SDRAM 写控制和完成脉冲 |
| `L=1, R=0, W=1, X=E` | 写完成先到但源结束未到 | 检查 BMP 结束条件及两个完成事件的时序关系 |
| `L=1, R=1, W=1, X=1` 且仍黑屏 | 显示已提交，故障在 SDRAM 数据正确性或读回链路 | 构建固定图案写入/读回诊断 |
| `X=1` 且图片正常 | 诊断构建改变了边缘时序表现 | 重复冷启动并优先处理 SDRAM 时序约束 |

## 验收标准

- 六位数码管能够稳定显示 `S C L R W X`，无肉眼可见闪烁或乱码；
- `KEY1` 能清除所有粘滞事件并重新启动原流程；
- 诊断版保持原有 HDMI 信号和 TF 扫描行为；
- 一次上板测试即可把故障至少缩小到“首图未启动”“BMP 源未结束”“SDRAM 写完成未到”或“提交后读回失败”中的一类；
- 测试结果和下一步结论补充到 `docs/project-roadmap.md`。
