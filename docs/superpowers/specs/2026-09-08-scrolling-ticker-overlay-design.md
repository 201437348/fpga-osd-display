# 动态字幕图层叠加设计

日期：2026-09-08

## 目标

在已固化并通过板测的 HX4S20C HDMI 多媒体播放系统中，增加一条独立的
动态滚动字幕，完成赛题“图层叠加与字幕效果”扩展要求的一项可演示功能。

字幕必须在正常图片显示、手动切图、自动轮播、音乐播放、TF 拔出等待和
回插恢复过程中持续且平滑显示。它不得改变 BMP 读取、SDRAM 双缓冲、音频
FIFO、HDMI 时序、按键含义或既有热拔插恢复协议。

## 选择范围

本项只实现固定英文展示标语的循环横向滚动，不实现文件读取字幕、多语言
字库、按键编辑文本、转场、亮度/对比度调节或音频可视化。这些功能将在本项
稳定后分别评估。

固定标语使用 ASCII 字符：

```text
FPGA HDMI MULTIMEDIA DISPLAY / TF IMAGE / 48K AUDIO /
```

标语首尾各保留一个空格，形成循环时的可辨识间隔。渲染字库复用当前 8×7
字形、纵向每行放大两倍的显示方式；新增所需的 `H`、`U` 和 `8` 字形，
保持当前小型组合字形查询方式；不引入外部 ROM 或新的 BRAM。

## 架构

`video_osd_overlay` 继续作为唯一的视频后处理叠加层，输入和输出都保留在
25 MHz `video_clk` 域。模块在现有顶部标题栏与底部状态栏之间增加一个 24 像素
高的字幕带：`y=432..455`。这样它不覆盖顶部标题，也不覆盖底部 `IMAGE/LOAD/
WAIT TF` 状态信息。

```text
SDRAM 图像 / 回退图 ──> 现有 OSD 顶栏 ──> 字幕带 ──> 现有状态栏 ──> HDMI
                                      ↑
                              video_clk 帧计数 + 滚动偏移
```

字幕的字符像素与现有 OSD 一样在组合逻辑中根据当前像素坐标和 8×7 字形
生成，并将每一行纵向放大两倍，形成 8×16 的屏幕显示高度。字幕带背景使用与
OSD 统一的深色风格实色背景；字符使用高对比
浅色。显示端没有 alpha 混合、SDRAM 读写或跨时钟信号，因此不会改变帧缓存
控制路径。

## 运动规则

滚动偏移仅在 `vs` 上升沿更新，保证一个完整显示帧内字幕位置不变。每经过
三个输出帧，偏移向左移动一个像素，约为 20 像素每秒。标语首尾各保留一个
字符空白，并在完整标语宽度后从右侧无缝继续，形成持续循环。

在复位、无有效图像、回退彩条、`WAIT TF`、`SCAN`、`LOAD`、自动轮播和手动
切图期间，滚动计数器不停；只有用户逻辑复位才使偏移回到初始位置。这体现
字幕层独立于存储和播放状态。

## 接口与资源

`video_osd_overlay` 的现有端口保持不变。字幕所需的坐标、帧分频计数、像素
偏移和字形选择全部在模块内部完成。顶层、SDRAM、TF、音频、按键、约束和
生成 IP 均不修改。

预期成本仅为少量 25 MHz 组合逻辑和寄存器；不增加 BRAM、DSP、PLL 或外部
带宽。当前项目资源余量足够，但以 TD `syn_1`/`phy_1` 实测报告为准。

## 异常策略

字幕不可依赖 TF 文件、音频数据或帧缓存内容，因此不会因为无卡、WAV 无效、
读图失败或音频静音而停止。若现有系统进入彩条回退，字幕仍展示；这使回退
状态在现场可辨识，同时保留现有底部 `FALLBACK` 文字。

## 验证

仿真新增或扩展 OSD 单元测试，检查：

1. 字幕带内背景与字形像素正确覆盖输入 RGB；
2. 字幕带外的已有标题、状态栏和普通图像像素保持原有行为；
3. 偏移只在帧边界更新，三个完整帧后左移一个像素；
4. 偏移在标语全长后正确回绕；
5. `display_valid`、`storage_ready`、加载状态变化不复位或冻结字幕。

通过 Icarus 后，用户在 TD GUI 运行 `syn_1` 和 `phy_1`，以 JTAG 下载验证：

1. 字幕连续平滑滚动且容易看清；
2. 首图、`KEY2` 手动切图和 `KEY4` 自动轮播保持正常；
3. HDMI 音乐无中断；
4. TF 拔出显示 `WAIT TF`、回插自动恢复时字幕仍存在；
5. 全部通过后才考虑更新配置 Flash。

## 非目标

本项不改变现有的固定 `640x480` BMP 输入约束，不实现图片缩放、淡入淡出、
亮度/对比度控制、每图独立音频或频谱/波形。尤其不修改已经稳定但时序敏感
的 SDRAM 双缓冲读写数据路径。
