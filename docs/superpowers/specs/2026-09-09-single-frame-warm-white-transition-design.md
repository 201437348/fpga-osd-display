# 单帧暖白淡化转场设计

日期：2026-09-09

## 目标

消除双帧交叉淡入淡出在开发板上仍然出现的转场花屏，同时保留明确、流畅且适合
比赛展示的换图效果。转场总时长控制在约 0.53 秒，并用可辨识的暖金色斜向扫光
替代当前过浅、容易被误认为视频撕裂的软白线条。

## 板测结论与取舍

当前 0 到 64 的双帧交叉淡入淡出已将视觉步进改善到约 1.08 秒，但最新 JTAG
板测仍出现花屏。三个针对性仿真只能证明控制、混色和理想化 SDRAM 返回路由正确，
无法证明器件上的双 FIFO 并发回读在既有负时序裕量下稳定。

按照上一轮稳定性设计中已经规定的回退条件，本轮不再增加双帧调度器复杂度，而是
改为单帧淡到暖白、在全白遮罩下切换显示缓冲区、再从暖白淡入新图。任一时刻只读取
一张完整画面，从架构上移除转场专属的双帧带宽、第二读 FIFO 和返回路由风险。

## 视觉行为

- 首图直接显示，不播放转场。
- 正常 `KEY2` 或 `KEY4` 换图时，在下一个视频帧边界开始转场。
- 前 16 帧保留旧图并逐帧向暖白淡化；中点达到完整暖白时切换缓冲区；后 16 帧让
  新图从暖白恢复，约 0.53 秒完成。
- 采用 0 到 64 的遮罩强度和 16 段对称缓入缓出曲线
  `0,1,2,4,7,11,16,23,32,41,48,53,57,60,62,63,64`。端点变化细、中段变化快，
  在约半秒总时长下减轻固定 6.25% 线性跳变的阶梯感；像素插值仍只需移位除以 64。
- 一条 40 像素宽的暖金色斜向扫光随转场从左上方向右下方向移动。外缘向
  `24'hFFD166` 插值四分之一，16 像素核心区插值二分之一，使它看起来是有意设计的
  金色光带，而不是低对比度撕裂线。
- 扫光和暖白遮罩只作用于图片区，不覆盖顶部标题、滚动字幕和底部状态栏。
- 音乐在转场期间连续播放，按键与自动轮播在转场忙时继续沿用现有互锁。

## 架构

### 视频域控制器

`video_transition_controller` 保留已提交缓冲区检测和帧边界启动逻辑，但不再请求
双帧读取。它输出当前应读取的 `active_buffer_index`、转场活动信号、0 到 64 的
`fade_level`，以及独立的 0 到 64 单向 `sweep_position`。

转场开始时锁定目标缓冲区。淡出阶段让 `fade_level` 按缓入缓出曲线从 0 递增到
64；到达 64 的帧边界时把 `active_buffer_index` 切换为目标缓冲区；淡入阶段再按
反向曲线从 64 递减到 0。只有淡入结束后才清除转场忙信号并释放下一次加载请求。
`sweep_position` 在完整 32 帧转场中每帧增加 2，不跟随先升后降的遮罩强度，保证
金色斜向光带只向前扫过一次而不会在后半段原路倒退。

### SDRAM 读取

`top.v` 始终以 `active_buffer_index` 发起单帧读取。`frame_read_write` 的接口和内部
实现均恢复到板测稳定版本使用的单个读 FIFO 和 `frame_fifo_read` 调度器，不再暴露
旧帧或双读端口。第二 FIFO 调度器文件仅为历史追溯继续留在仓库中，不再被显示路径
实例化，因此不会占用综合资源或参与时序。

### 像素效果

`video_transition_blender` 改为单输入效果器。基础像素先按 `fade_level / 64` 向暖白
目标 `24'hFFF4D6` 插值，再在斜向带内向金色 `24'hFFD166` 做饱和安全的正负差值
插值。斜向带位置由 `sweep_position` 决定。所有通道运算先扩位并根据目标与输入的
大小选择加法或减法，避免无符号回绕。

OSD 继续在效果器之后合成，因此不受淡化和扫光影响。

## 异常与边界

- 转场过程中若出现新的缓冲区提交，只保留最新目标，并在本次转场完成后由现有播放
  互锁恢复正常加载；正常路径下加载在转场忙时不会启动。
- TF 拔出沿用存储故障优先策略。已经开始的转场只访问两个已写完的 SDRAM 缓冲区，
  可完成后停留在最后稳定画面。
- 非转场期间效果器必须逐像素直通，不改变静态图片、彩条或 HDMI 时序。

## 验证

仿真覆盖：首图直通、16 帧淡出、全暖白切换、16 帧淡入、最终释放、缓冲区只在
全遮罩帧切换、非转场精确直通、暖白端点、金色核心和外缘、图片区外不加扫光、顶层
固定单帧读取以及现有 OSD 行为。

开发板验证使用 JTAG：至少连续执行十次 `KEY2` 换图和多轮 `KEY4` 自动轮播，确认
无矩形花屏、撕裂、黑帧或 HDMI 失锁；扫光应明显呈暖金色且不会被误认为异常条纹；
同时检查音乐、OSD 和一次 TF 拔插恢复。全部通过后才考虑更新配置 Flash。

## 范围

本轮不改变 BMP/WAV 格式、FAT32、SDRAM 写入、音频、PLL、HDMI 时序、OSD 内容、
按键定义、自动轮播间隔或内存地址。重点只包括转场控制、单帧像素效果、顶层读取选择
和相关测试。
