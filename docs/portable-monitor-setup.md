# 便携式显示屏设置指南（16 英寸 2.5K 144Hz）

适用：自备演示显示设备。评委不提供显示设备，所以**这块屏的 OSD 设置会直接影响
评委看到的画面**——显示器自带的锐化、降噪、过扫描都会被当成你 FPGA 输出的效果。
本文件说明怎么把它调到"尽量透明"。

---

## 一、先搞清楚 FPGA 到底送出了什么

| 项目 | 实测值 | 说明 |
| --- | --- | --- |
| 有效分辨率 | **640 × 480** | `video_define.v` 定义 `VIDEO_640_480` |
| 宽高比 | **4:3** | 不是 16:9 |
| 行总长 / 场总长 | 800 / 525 | 标准 VGA 时序 |
| 像素时钟 | **25.000 MHz** | `video_pll` 实测输出（标准 VGA 是 25.175 MHz） |
| 刷新率 | **59.52 Hz** | 25 000 000 ÷ (800×525)；标准值是 59.94 Hz |
| 色彩 | RGB888（24 位） | — |
| 音频 | HDMI 内嵌 48 kHz PCM | 需显示器喇叭能出声 |

**两个关键结论：**

1. **信号是 4:3**。你之前看到的"宽屏"是显示器把 4:3 横向拉伸铺满 16:9，
   画面本来就是变形的。切到"自动"后显示器按 4:3 正确显示——这一步是显示器做对了。
2. **刷新率是 59.52 Hz 而不是 59.94 Hz**（因为用了 25.000 MHz 而不是 25.175 MHz，
   偏差 −0.7%）。绝大多数显示器能锁，但个别挑食的屏可能报"超出范围"或闪烁。
   如果遇到，这是候选原因（见第五节排查）。

---

## 二、你的屏会把 640×480 放大成什么

按 4:3 保比例、适配到屏幕（缩放系数取 `min(屏宽/640, 屏高/480)`）：

| 屏规格 | 4:3 画面显示为 | 占屏宽 | 占屏高 | 放大倍数 | 左右黑边 |
| --- | --- | --- | --- | --- | --- |
| **2560×1600（16:10）** | **2133×1600** | **83.3%** | **100%** | 3.33× | 每侧 213 px |
| 2560×1440（16:9） | 1920×1440 | 75% | 100% | 3.0× | 每侧 320 px |

> **更正**：本文档早先版本写成"2560×1600 → 1600×1200，占屏宽 62.5%"，
> 那是把缩放系数算成了 `min(屏宽/640, 屏高/480)` 中的**宽度项**，属于算术错误。
> 正确结果是按高度适配的 **2133×1600**，占屏宽 83.3%、占屏高 100%。

**结论：两种屏都是满高显示、左右留黑边**，画面尺寸完全够演示。
在 2560×1600 上，画面占 83.3% 宽、100% 高，属于正常可接受的 4:3 呈现方式
（类似在宽屏显示器上看 4:3 视频），**不需要改 FPGA 的输出时序**。

如果选"点对点 / 1:1"，则是 640×480 原尺寸居中，只占屏宽 25%、屏高 30%——
很小，但**显示器完全不做缩放，看到的是你 FPGA 的真实输出像素**，
适合近距离验证缩放质量。

---

## 二之二、为什么不能把输出改成 2560×1600

这是被反复问到的问题，这里一次性写清楚。**2560×1600 在本平台上不可能实现**，
有四个互相独立、各自都足以否决的硬约束：

| # | 约束 | 2560×1600@60 需要 | 本平台能力 | 结论 |
| --- | --- | --- | --- | --- |
| 1 | **帧缓存容量** | 4,096,000 字/帧，双缓冲 8,192,000 字 | SDRAM = 2^21 = **2,097,152 字**（8 MB） | 单帧就是全部 SDRAM 的 **1.95 倍** |
| 2 | **SDRAM 带宽** | 245.76 M 字/秒 | 125 MHz × 32 bit = **125 M 字/秒** | 差 **2 倍** |
| 3 | **像素时钟 / 视频域 Fmax** | ≈268.5 MHz | 当前 `video_clk` 25 MHz，实测 **Fmax 仅 34.943 MHz** | 需要 **10.7 倍**提速 |
| 4 | **TMDS 速率** | 2.685 Gbps/lane | HDMI 1.4b 核在 EG4 上的常规上限约 1080p60（1.485 Gbps） | 超出 |

帧缓存格式是 **1 像素 = 1 个 32 位字**（`FRAME_PIXELS = 307200`，`BUF1_ADDR` 紧随其后，
`ADDR_WIDTH = 21`），所以约束 1 无法靠"压缩存储"绕过——即使改成 16 位色深，
单帧也要 2,048,000 字（占满 97.7%），双缓冲仍然装不下，而带宽依然贴着 125 M 字/秒 的天花板。

### 各分辨率的可行性天花板

| 目标分辨率 | 宽高比 | 像素时钟 | 双缓冲占用 / 2.1M 字 | 读带宽 / 125M | 可行性 |
| --- | --- | --- | --- | --- | --- |
| 640×480（当前） | 4:3 | 25.0 MHz | 0.61M（29%） | 18.4M（15%） | ✅ 现状 |
| **800×480** | **5:3** | **32.0 MHz** | **0.77M（37%）** | **23.0M（18%）** | ⚠️ **唯一可行的升级** |
| 1024×600 | 约 16:10 | 49.0 MHz | 1.23M（59%） | 36.9M（30%） | ❌ 需重做视频域流水线 |
| 1280×720 | 16:9 | 74.25 MHz | 1.84M（88%） | 55.3M（44%） | ❌ 需重做视频域流水线 |
| 1280×800 | **16:10** | 83.5 MHz | 2.05M（**97.7%**） | 61.4M（49%） | ❌ 时钟需 2.4 倍 + 内存几乎占满 |
| 1920×1080 | 16:9 | 148.5 MHz | 4.15M（**198%**） | 124M（99%） | ❌ 内存和带宽双超 |
| 2560×1600 | **16:10** | 268.5 MHz | 8.19M（**391%**） | 246M（**197%**） | ❌ **不可能** |

**唯一现实的升级是 800×480（5:3 = 1.667）**，在 2560×1600 屏上按
`min(2560/800, 1600/480) = 3.2` 显示为 **2560×1536**，即占屏宽 **100%**、占屏高 96%，
只有上下各 32 px 黑边——几乎满屏。

但它的代价不小，必须一起改：

1. `video_define.v` 切到 `VIDEO_800_480`（厂商已预置该参数集，`V_TOTAL=505` → 32 MHz）
2. **新增 PLL 输出**：32 MHz（视频）+ 160 MHz（HDMI 串行），现为 25 / 125 MHz
3. `FRAME_PIXELS` 307200 → 384000，`BUF1_ADDR` 随之改变
4. **全部 OSD 坐标重算**：顶部标题栏、底部状态栏、滚动字幕、音频柱、参数面板、字模列定位
5. 缩放器 `DST_WIDTH` 640 → 800
6. **音频 ACR 的 N/CTS 值**（依赖像素时钟）
7. 帧 FIFO 深度 / 读突发长度（行长 800 → 1056 含消隐）
8. **视频域时序重收敛**：当前 Fmax 34.943 MHz，32 MHz 只剩约 9% 余量，风险偏高
9. 上述全部功能重新上板验收

**结论：现在不要改。** 640×480 在你屏上已经是"满高 + 83.3% 宽"的正常 4:3 呈现；
真正需要修的是**过扫描导致的边缘裁切**（见第五节），那和分辨率无关。
等缩放功能与验证全部冻结之后，如果还有时间、且确认观感确实不够，再单独立项做 800×480。

## 三、必须改的 OSD 设置（按重要性排序）

菜单名称各品牌不同，下面给出中英文对照。

| 设置项 | 菜单里可能叫 | **设成** | 为什么 |
| --- | --- | --- | --- |
| 画面比例 | 图像比例 / Aspect Ratio / 显示比例 | **自动 (Auto)** 或 **4:3** | 选 16:9 / 全屏 / Wide 会把 4:3 拉伸变形 |
| 过扫描 | Overscan / 扫描模式 / Just Scan / 全屏扫描 | **关**；有"点对点/1:1"时按需 | 过扫描会切掉画面边缘的标题栏和参数面板 |
| 锐度 | Sharpness / 清晰度 | **最低或中间** | 显示器锐化会放大缩放的锯齿，让评委误判你的画质 |
| 降噪 | Noise Reduction / NR / 数字降噪 | **关** | 会抹掉细节，直接影响"缩放质量"的对比效果 |
| 动态对比度 | DCR / 动态对比度 / 自动对比度 | **关** | 会随画面内容改亮度，掩盖你的亮度/对比度调节 |
| HDR | HDR / HDR10 | **关** | 640×480 无 HDR 元数据，开着会偏色发灰 |
| 图像模式 | Picture Mode / 场景模式 | **标准 (Standard)** 或 **游戏 (Game)** | 不要用"动态/鲜艳/Vivid"，会加锐化和饱和度 |
| 色温 | Color Temperature | **标准 / sRGB** | 偏色会影响你对图像的判断 |
| 低蓝光 | Low Blue Light / 护眼模式 | **关** | 会整体偏黄 |
| 自适应同步 | FreeSync / G-Sync / Adaptive-Sync | **关** | 60 Hz 输入用不到，某些屏会引起闪屏 |
| 响应时间 | Overdrive / Response Time | **中或低** | 开最高会有过冲白边 |
| 背光/亮度 | Brightness | 舒适即可 | 只影响观感，不影响正确性 |
| HDMI 版本 | HDMI 1.4 / 2.0 | **1.4 或 自动** | 本设计是 HDMI 1.4b |

## 四、两套推荐配置

### A. 演示配置（比赛现场用）

- 画面比例：**自动 / 4:3**
- 过扫描：**关**（没有该选项就选 Just Scan / 全屏扫描）
- 锐度最低、降噪关、DCR 关、HDR 关、图像模式标准、色温标准
- 效果：4:3 画面满高显示、左右黑边，内容完整不裁切

### B. 验证配置（上板自测画质时用）

- 在 A 的基础上把画面比例改成 **点对点 / 1:1**
- 效果：显示器零缩放，看到 640×480 原始像素
- 用途：验证"最近邻 / 双线性 / 面积平均"三种模式的真实差异；
  在 A 配置下显示器的缩放器会叠加自己的滤波，干扰判断
- 更严谨的做法：用 HDMI 采集卡抓帧，离线对比（完全排除显示器影响）

## 五、上板验证步骤（按顺序做）

1. **确认能锁信号**：接上 HDMI，看显示器是否稳定显示、是否报"超出范围 /
   Out of Range / 不支持的分辨率"。能稳定显示才继续。
2. **切到边缘测试图案**（prompt 任务 C 新增）：
   - 最外圈 1px 白框是否四边都完整可见？
   - 1% / 2% / 3% / 5% / 8% / 10% 刻度里，**最外圈可见的是哪一档**？
     → 这就是你显示器的实际过扫描比例
   - 安全区青色边框是否完整可见？
3. **按实测值定安全区**：如果 3% 刻度都看不见，把 `SAFE_MARGIN_X/Y` 加大；
   如果连 1% 都看不见，说明过扫描很严重，优先去 OSD 里找"过扫描/Just Scan"关掉。
4. **验证音频**：确认声音从显示器喇叭出来（或外接音箱）。
   官方要求自备设备必须能播放 HDMI 音频。
5. **验证画质模式**：切到 1:1 配置，用 1920×1080 测试图对比三种重采样模式。

## 六、排查表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 报"超出范围 / Out of Range / 无信号" | 显示器不接受 640×480；或 25.000MHz 偏差导致锁不住 | 换 HDMI 口；OSD 里找"HDMI 版本"设 1.4；确认输入源选对。仍不行见第七节 |
| 画面闪烁或偶尔黑一下 | 自适应同步（FreeSync）干扰；或像素时钟偏差 | 关 FreeSync / Adaptive-Sync |
| 画面横向拉长、人脸变宽 | 画面比例设成了 16:9 / 全屏 | 改成 自动 或 4:3 |
| 顶部标题栏 / 右侧参数面板被切 | 显示器过扫描 | OSD 里关过扫描 / 选 Just Scan；同时按 prompt 任务 C 加安全区 |
| 画面边缘有一圈白边或过冲 | 响应时间/Overdrive 开太高 | 调到中或低 |
| 画面发灰、颜色淡 | HDR 开着 | 关 HDR |
| 文字边缘有彩色镶边 | 显示器锐化 + 缩放器色度处理 | 锐度调到最低 |
| 图片看起来有摩尔纹/锯齿 | 这可能是**你的缩放器真的在混叠**（当前实现的问题），也可能叠加了显示器缩放 | 切 1:1 配置再看：1:1 下还有 → 是你的问题（正是 prompt 任务 A 要修的）；1:1 下没有 → 是显示器缩放 |
| 没有声音 | HDMI 音频未握手 / 显示器喇叭静音 | 检查显示器音量、确认音频源是 HDMI；必要时外接音箱 |

## 七、如果这块屏死活不接受 640×480

640×480 属于 VESA 标准"established timing"，绝大多数显示器 EDID 里都有，
**但部分高分辨率高刷面板确实砍掉了 VGA 模式支持**。所以**务必提前测**，别到现场才发现。

备选方案（按代价从小到大）：

1. **换 HDMI 接口**：你的板子有双 HDMI，换另一个口试。
2. **换一台显示设备**：借一台电视或普通显示器，640×480 兼容性最好。
3. **加一个 HDMI 转接/分配器**：中间加一级 scaler（如 HDMI 转 VGA + 显示器），
   这类设备通常强制支持低分辨率输入。
4. **改 FPGA 输出时序**（最后手段）：厂商代码 `color_bar.v` 里已经预置了
   `VIDEO_800_480`（800×480，33 MHz，5:3）和 `VIDEO_1280_720`（720p）参数集。
   但切换会牵动 **PLL 时钟、SDRAM 带宽、全部 OSD 坐标、缩放器目标尺寸、
   音频 ACR 的 N/CTS**，等于把视频通路重做一遍，而当前 LUT 已用 86%。
   **除非第 1~3 项都失败，否则不要动。**

## 八、给比赛现场的准备清单

- [ ] 便携屏 + 电源 + HDMI 线（多带一根备用）
- [ ] **显示器的遥控器或按键说明**——现场可能需要快速切"4:3 / 点对点"
- [ ] 提前把第三节的设置改好并**记住菜单路径**
- [ ] 确认音频能出声（自带喇叭或外接音箱）
