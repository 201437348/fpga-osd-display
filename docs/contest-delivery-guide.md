# OSD 图片轮播与 HDMI 音频展示系统

更新日期：2026-09-08

## 成品定位

本作品是运行于康芯 HX4S20C（安路 EG4S20BG256）的无处理器商显
展示终端。FPGA 从 FAT32 TF 卡根目录读取图片和背景音乐，通过片内
SDRAM 双缓冲输出 HDMI 图像和 48 kHz HDMI 音频，并提供板载按键交互、
自动轮播、状态 OSD 与 TF 热拔插自动恢复。

## 已交付功能

| 功能 | 成品行为 |
| --- | --- |
| 图片文件系统 | 扫描 FAT32 根目录，按 FAT 簇链读取文件；BMP 不要求物理连续存储。 |
| 图片显示 | 显示最多四张 640x480、24-bit、非压缩 BMP；使用 SDRAM 双缓冲，加载完成后再切换显示。 |
| 图片控制 | `KEY2` 手动切下一张；`KEY4` 开启或关闭自动轮播；短间隔按键请求会合并，避免重复加载。 |
| HDMI 音频 | 读取根目录 `BGM.WAV`，输出 48 kHz 双声道 PCM；音乐独立于图片切换持续播放，播完自动循环。 |
| OSD | 画面顶/底栏显示系统标题和图片、加载、存储状态；中下方叠加固定 ASCII 滚动字幕。 |
| 异常恢复 | 无卡启动显示彩条回退；运行中拔卡保留当前图片并静音；回插后自动重新扫描、保留原图并从头恢复音乐。 |

## 现场准备

### 硬件连接

1. 开发板通过 USB 连接下载器。
2. HDMI 线连接板卡 `HDMI_B` 与带扬声器的显示器。
3. 显示器切换到对应 HDMI 输入，并调高显示器音量。
4. 在断电状态插入准备好的 TF 卡，再上电或通过 TD JTAG 下载当前工程生成的 bitstream。

### TF 卡媒体规范

TF 卡必须使用 FAT32 文件系统，媒体文件放在根目录。

| 文件 | 要求 |
| --- | --- |
| 图片 | 最多 4 张；`640x480`；Windows BMP；24-bit RGB；无压缩。 |
| 音乐 | 文件名必须为 `BGM.WAV`；RIFF/WAVE；signed PCM；`48000 Hz`；双声道；16-bit little-endian。 |

项目同时兼容官方示例使用的 48 kHz、双声道、24-bit
`WAVE_FORMAT_EXTENSIBLE` PCM WAV，但最终展示优先使用 16-bit PCM，
以降低 TF 读取带宽和片上 FIFO 资源。

不要使用 exFAT、压缩 BMP、PNG/JPG，或任意采样率/声道数的 WAV。当前
版本没有文件浏览、播放列表、音量调节或图片缩放功能。

## 按键与状态

| 板载按键 | 行为 |
| --- | --- |
| `KEY1` | 复位用户逻辑并重新启动 TF 扫描。 |
| `KEY2` | 手动切换到下一张图片。 |
| `KEY4` | 开启或关闭自动轮播。 |

运行中，OSD 的 `IMAGE` 表示正常显示，`LOAD` 表示正在加载下一张，
`WAIT TF` 表示检测到存储不可用。回插后内部会短暂扫描目录；扫描通常
少于一个显示帧，肉眼可能直接看到 `WAIT TF` 回到 `IMAGE`，这是正常行为。

## 三分钟演示脚本

1. 断电插卡、上电或下载当前 bitstream，展示首图、OSD 与背景音乐。
2. 按一次 `KEY2`，展示下一张图片切换，而音乐保持连续播放。
3. 按一次 `KEY4`，展示自动轮播；再次按下关闭自动轮播。
4. 在图像和音乐正常时拔出 TF 卡：展示 `WAIT TF`、当前图片保持、音乐静音。
5. 插回 TF 卡：无需按键，展示原图保持、OSD 自动回到 `IMAGE`、音乐从头恢复。
6. 说明背景音乐已实测完整播放约五分半，并在末尾立即从头循环。
7. 展示字幕带持续平滑滚动；说明字幕与图片、音频和 TF 状态独立。

## 工程与验证边界

- 工程入口：[osd_display.al](../fpga/osd_display/osd_display.al)。
- 当前最终功能以 TD GUI 的 `syn_1`、`phy_1` 和 JTAG 板测为准；本阶段不从命令行调用 TD。
- 本工程最近一次记录的实现资源为 8728/19600 LUT、6255/19600 REG、24/64 BRAM9K、10/29 DSP。长 WAV 修复只是读文件簇链上限参数，不增加存储资源。
- 已知布线报告仍包含继承自 SDRAM 基线的负建立裕量；当前板卡已通过上述功能和稳定性测试，但它不应被表述为时序已完全收敛。
- 当前稳定版本已写入配置 Flash，并完成板端复测；字幕版本已通过 JTAG 板测，可作为后续功能冲刺前的可回退基线。每次新增功能仍应先用 JTAG 验收，确认不退化后再决定是否更新 Flash。
- 当前成品已完成稳定性和媒体播放验收，但不等同于比赛目标已经封版。下一阶段先依据正式赛题重建“评分要求—现有能力—缺口—验收”的目标矩阵，再决定仅补足基础评分项，还是加入有把握的可选展示功能。
