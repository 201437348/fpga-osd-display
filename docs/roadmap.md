## 1. 项目目标

作品面向数字广告牌和商业展示终端，在不使用外部处理器的前提下，由 FPGA 完成 TF 卡文件读取、图片解析、SDRAM 帧缓存、HDMI 音视频输出和按键交互。

计划实现的主要功能：

- FAT32 文件系统解析和 BMP 图片读取；
- SDRAM 双帧缓存及稳定的图片轮播；
- HDMI 640x480@60Hz 视频输出；
- OSD 菜单、文字和参数信息叠加；
- 按键调节亮度、对比度、音量、静音和播放状态；
- 动态滚动字幕和图片转场；
- 不同分辨率图片的缩放，先实现最近邻，再升级双线性插值；
- 48kHz PCM WAV 播放及 HDMI 音频输出；
- 异常图片或音频文件的超时恢复和静音保护；
- 时间和资源允许时增加音频波形或简化频谱显示。

其中 HDMI 音频属于 2026 赛题基础评分项，不作为最后才考虑的附加功能。

## 2. 2026 资源包审查结论

资源包位置：`D:\HX4S20_Contest_202606`

### 2.1 可复用内容

`lab_ex4_tf` 提供：

- TF 卡 SPI 扇区读取；
- 640x480、24 位、非压缩 BMP 检测；
- SDRAM 双帧缓存；
- HDMI 640x480@60Hz 输出；
- 最多 4 张图片的手动切换和自动轮播；
- PLL 连续稳定约 20ms 后释放复位；
- 图片加载超时和部分跨时钟完成信号保护。

`lab_ex5_i2s` 提供：

- 48kHz、24 位双声道 PCM 到 HDMI IP 的接口；
- I2S 测试音发生器和 I2S 接收模块；
- HDMI ACR 参数生成，示例使用 `N=6144`；
- HDMI 音视频合流和输出连接方式。

通用 `31_hdmi_tx_display_B` 例程可用于验证 HDMI_B 接口和显示器，不依赖 TF 卡。

### 2.2 不能直接当成成品的部分

- 当前图片例程不是真正的 FAT32 解析，而是扫描物理扇区寻找 `BM` 文件头；
- 扫描范围默认为前 131072 个扇区，即前 64MiB；
- 最多记录 4 张图片，并假定图片数据连续存放；
- 只支持固定的 640x480、RGB24、非压缩 BMP；
- 没有 OSD、亮度、对比度、字幕、转场或图片缩放；
- 音频例程只播放 FPGA 内部生成的测试音，没有从 TF 卡解析和播放 WAV；
- 通用 `18_sd_card_audio` 实际只是 SD 卡扇区读写验证，不能直接播放音频；
- 例程文档和工程名称存在复制错误，功能判断必须以源码、仿真和上板结果为准。
- 资源包保留了多个时期的 `.bit` 和 `_Runs` 目录；`best_result` 只表示某次构建保存的结果，不保证与所在目录的当前 `.al` 工程对应。选择 bitstream 时必须核对工程名、生成时间和构建报告。

已确认的混合产物：

- `31_hdmi_tx_display_B\prj\hdmi_tx_display.bit` 是 2022 年旧文件；2025 年重新构建且已上板通过的是 `hdmi_tx_display_Runs\best_result\hdmi_tx_display.bit`；
- `lab_ex4_tf\src\td_project` 当前只有 `lab_ex5_i2s_v1.0.al`，但同时残留 `HDMI1.4b_Transmitter_v1.0_Runs`；
- 上述残留目录中的 2026-04-24 bit 与独立 `lab_ex5_i2s` 音视频例程的 bit 哈希完全相同，不能当作当前纯视频工程的构建结果；
- 当前纯视频工程对应的 2026-06-05 bit 位于 `lab_ex5_i2s_v1.0_Runs\best_result`，其 `best_result` 与 `phy_1` 文件哈希相同。

### 2.3 底座选择

正式项目以 `lab_ex4_tf` 为可靠性底座，只从 `lab_ex5_i2s` 移植音频 PLL、测试音、I2S 接收、ACR 和 HDMI 音频接口。

不整体采用 `lab_ex5_i2s`，因为它的统一复位只检查音频 PLL，缺少 `lab_ex4_tf` 中的系统/视频 PLL 稳定等待，并删除了部分图片加载超时保护。

## 3. 已知资源与风险

- 芯片资源：19600 LUT、19600 寄存器、4 个 PLL，片内集成 2M x 32bit SDRAM；
- 640x480 RGB888 在例程中按每像素 32 位存储，一帧约 1.23MB，双缓冲约 2.46MB；
- 视频例程约使用 18% LUT、16% 寄存器、22% BRAM 和 2 个 PLL；
- 加入测试音后约使用 20% LUT、19% 寄存器、31% BRAM 和 3 个 PLL；
- LUT 余量较充足，但 BRAM、最后一个 PLL、SDRAM 带宽和 TF 卡仲裁需要提前规划；
- 官方现有布局布线报告的最差建立时间裕量约为 `-6.6ns`，可能混有未正确约束的跨时钟路径，但必须审查，不能直接忽略；
- 双线性插值、完整 FAT32 和 TF 卡 WAV 流播放是本项目难度最高的部分，必须分阶段验证。

### 稳定基线（不要回退）

阶段 6 验收通过的无羽化生产配置，是后续所有开发的回归基线。
禁止修改已验收的 SDRAM 滑动调度、时钟、FIFO 深度和固定 burst 策略：

```verilog
.WRITE_BUFFER_SOLID_DIAGNOSTIC(0),
.SLIDE_FEATHER_ENABLE(0),
.SLIDE_FIFO_UNIFORM_DIAGNOSTIC(0),
.SLIDE_SDRAM_UNIFORM_DIAGNOSTIC(0),
.SLIDE_READ_ADDRESS_PATTERN_DIAGNOSTIC(0),
.SLIDE_PHASE_COLOR_DIAGNOSTIC(0),
.READ_CHUNK_PREROLL_WORDS(4),
.FIXED_READ_BURST_ENABLE(1),
```

任何新功能都必须先通过 Icarus 回归，再进入 TD 综合与 JTAG 上板验证。

### 已知未收敛项

- **SDRAM DQ 时序**：`SWNS = -6.565 ns`，与 2026-06-05 官方 `lab_ex4_tf` 基线完全相同，
  属官方底座固有行为。禁止用 `false_path` 屏蔽。详见 `history/board-log.md`。
- **`rst_all` 跨时钟域释放**与 **`ext_mem_clk -> sd_card_clk` FIFO 异步清零**：独立审查项。
- **Flash 固化验收**：赛题基础要求「上电即可运行」，需用最新 bit 重新固化并冷启动验证。
