## 1. 现状与问题（已实测，作为设计输入）

### 1.1 缩放器当前对常见分辨率实际上不插值

`rtl/image/image_bilinear_scaler.v` 用 `STEP = floor(srcW·2^F/dstW)`、`fx = fix & (2^F-1)`
做定点步进。当 `srcW·1024/640` 是 1024 的整数倍时 `fx ≡ 0`，插值项恒为零，
输出退化为 `p[3i]` 纯点采样：

| 源分辨率 | X 插值 | Y 插值 | 实际抽样 |
| --- | --- | --- | --- |
| 1920×1080 | **失效(0% 像素)** | 激活 | 水平纯点采样，丢 2/3 列 |
| 1280×960 | **失效(0%)** | **失效(0%)** | 双向纯点采样 |
| 1280×720 | **失效(0%)** | 激活 | 水平纯点采样 |
| 1920×1200 | **失效(0%)** | 激活 | 水平纯点采样 |

规律：`srcW ∈ {640,1280,1920}` 或 `srcH ∈ {480,960}` 时该方向插值失效。

### 1.2 2 抽头双线性本身不抗混叠

缩小时 2 抽头双线性是"重建滤波器"，不是"抗混叠预滤波器"：1920→640 每个输出像素
只读 2 个源像素，理想面积滤波应平均约 9 个。这是"鼓励优化缩放质量"要解决的问题。

### 1.3 拉伸铺满导致变形

当前 X、Y 独立映射铺满 640×480，1920×1080 的图纵向被拉长 33%。官方叫"自适应"，
且框图里"缩放比"是单数，应按**保持宽高比**实现。

### 1.4 上板发现的显示裁切问题

- FPGA 输出时序确认：`rtl/vendor/SD/video_define.v` 定义 `VIDEO_640_480`，
  `rtl/vendor/SD/color_bar.v` 该分支为 `H_ACTIVE=640 / V_ACTIVE=480`
  （H_TOTAL=800，V_TOTAL=525）→ **输出是 4:3 的 640×480**。
- 显示器切到"自动"后按 4:3 正确显示（两侧黑边）。之前"宽屏"模式是显示器把 4:3
  信号横向拉伸铺满 16:9，画面本来就是变形的。
- 但画面内容在边缘被裁切。原因是**当前 OSD 布局几乎没有安全边距**：
  - `TOP_BAR` 从 `y=0` 开始 → 顶部边距 **0%**
  - 参数菜单面板右边界 `x=632` → 右侧边距 **8px = 1.25%**
  - 滚动字幕 `y=432..456` → 底部边距 24px = 5%（临界）
- 显示器在"自动"模式常带 3~5% 过扫描（overscan），顶部条和右侧面板必然被切。

### 1.5 缩放器验证状态

**零测试覆盖。** 注释引用的 `tools/bilinear_model.js`、`tools/scaler_cycle_model.js`、
`tests/tb_scaler_chain.sv` 三个文件**在仓库中不存在**。`tb_fat32_image_storage_adapter.sv`
的 BMP 场景默认 `AUDIO_ONLY=1` 被跳过，改回 0 会立即失败（fixture 声明 640×480 但只有
60 字节，且断言 `pixel_count==2`，与缩放器"恒输出 307200 像素"的语义结构冲突）。
本次必须补齐。

## 3. 任务 A：统一缩放比 + 保宽高比 + 黑边（核心）

### A.1 几何规格

```
s    = min(DST_W / srcW, DST_H / srcH)          // 统一缩放比，Q16 定点
ow   = floor(srcW * s)                           // 图像显示宽，<= 640
oh   = floor(srcH * s)                           // 图像显示高，<= 480
xoff = (DST_W - ow) >> 1                         // 水平居中偏移
yoff = (DST_H - oh) >> 1                         // 垂直居中偏移
黑边 RGB = 24'h000000
```

- `s` 用 Q16（16 位小数）表示，配置阶段用现有共享串行除法器计算，不新增除法器。
  若 LUT 紧张可用 `s = min(floor(640·2^16/srcW), floor(480·2^16/srcH))` 的保守下取整。
- **放大与缩小都要支持**：`s > 1` 放大（小图铺满），`s < 1` 缩小（大图适配）。
- 输出坐标 `(X, Y)` 到源坐标的映射：
  - 若 `X < xoff` 或 `X >= xoff+ow` 或 `Y < yoff` 或 `Y >= yoff+oh` → 输出黑边；
  - 否则 `sx = (X - xoff) · srcW / ow`，`sy = (Y - yoff) · srcH / oh`（定点，同现有机制）。
- 实测样例（必须与实现一致）：

| 源分辨率 | s | ow×oh | 黑边(上下) | r_x | r_y | 抽头 |
| --- | --- | --- | --- | --- | --- | --- |
| 640×480 | 1.0 | 640×480 | 无 | 1 | 1 | 2/2（恒等） |
| 800×600 | 0.8 | 640×480 | 无 | 1.25 | 1.25 | 3/3 |
| 1024×768 | 0.625 | 640×480 | 无 | 1.6 | 1.6 | 3/3 |
| 1280×720 | 0.5 | 640×360 | 60px | 2 | 2 | 3/3 |
| 1280×960 | 0.5 | 640×480 | 无 | 2 | 2 | 3/3 |
| 1440×1080 | 0.444 | 640×480 | 无 | 2.25 | 2.25 | 4/4 |
| 1600×1200 | 0.4 | 640×480 | 无 | 2.5 | 2.5 | 4/4 |
| 1920×1080 | 0.333 | 640×360 | 60px | 3 | 3 | 4/4 |
| 1920×1200 | 0.333 | 640×400 | 40px | 3 | 3 | 4/4 |
| 320×240 | 2.0 | 640×480 | 无 | 0.5 | 0.5 | 2/2（放大） |

### A.2 面积平均抗混叠滤波（本次核心得分点）

- **抽头数上界**：`r_x = srcW/ow ≤ 1920/640 = 3`，`r_y = srcH/oh ≤ 1080/480 = 2.25`
  （因为 `ow ≤ 640`、`oh ≤ 480`）。故 `taps = ceil(r) + 1 ≤ 4`，**两个方向都不超过 4 抽头**。
- **权重定义**（对输出像素 i，源方向步长 r）：
  足迹 `[i·r, (i+1)·r)`；源像素 k 的贡献 = 重叠长度
  `w_k = max(0, min((i+1)·r, k+1) − max(i·r, k))`；权重和恒为 `r`，归一化到 `2^F`。
  用定点实现，保证 `Σw_k = 2^F` 精确无偏（不能有累积误差）。
- **退化情形**：
  - `r ≤ 1`（放大）→ 用 2 抽头双线性（面积滤波在放大时退化为双线性，无需 4 抽头）。
  - `r` 为整数 → 权重为均匀 `1/r`，等价于 `r` 抽头箱式平均。
- **禁止**：不得为了省逻辑而回退成 2 抽头"近似"——那正是要修的问题。

### A.3 半像素中心对齐

现有 `sx0 = floor(i·srcW/640)` 采样点落在源像素**左边缘**，正确位置是
`(i+0.5)·srcW/640 − 0.5`。修正：累加器初值加偏置 `(STEP − 2^F)/2`，
使采样点落在像素中心。放大时此项影响明显，必须修。

### A.4 行缓存改造（BRAM 不增加）

- 现状：8 个 `lbuf_1024x24`（4 槽 × 2 半行），容量 2 行 × 2048 px，占 24 个 BRAM9K。
- 目标：**4 行 × 1920 px**（垂直 4 抽头所需），`1920×24 = 46080 bit`，
  每行约 6 个 BRAM9K → 4 行约 24 个 BRAM9K，**与原占用持平**。
- 寻址按 `MAX_SRC_WIDTH ≤ 1920` 重新推导，删除"半行"概念或保留但重算槽位映射。
- 若 4 行排布导致 BRAM 超限，允许降级为 **3 行 + 3 抽头垂直**，
  但必须在报告中明确说明并给出质量对比数据。

### A.5 吞吐约束（必须守住 7 拍/输出像素）

- 现有输出回路 `EM_P0..EM_P6` = 7 拍/像素，`640×480×7 = 2,150,400` 拍。
- 源流速率由 SPI 决定：spi_clk = 100MHz/((0+2)×2) = 25MHz，
  每源像素 3 字节 = 24 bit = **96 拍 @100MHz**。
- **4 个抽头必须并行**（新增约 3 个 8×11 乘法器），不得串行展开成更多拍。
  若必须串行，则重新推导下面的最小尺寸判据并如实报告。
- DSP 只剩 3 个，新增乘法器**优先用 LUT 实现**，不得让 DSP 超过 29。

### A.6 最小源尺寸判据（改为周期数比较）

- 原理：黑边不需要源数据，可以在源流结束后输出；**只有图像区域必须在源流结束前产出**。
  故约束为 `ow·oh·7 ≤ srcW·srcH·96`。
- 代入 `ow·oh = srcW·srcH·s²` 得 `s² ≤ 96/7 = 13.71` → **`s ≤ 3.70`**。
- **用周期数比较替换现有的 `MIN_SRC_PIXELS = 32000`**（`fat32_bmp_loader.v` 的
  `src_pixels_ok`）：接受条件改为
  `(ow * oh * 7) <= (srcW * srcH * 96)`，全部用 32 位显式补零运算避免截断。
- 效果：最小可用尺寸从 32000 px（约 179×179）放宽到约 **130×130**（s≈3.70）。
  这直接改善官方"任意分辨率图片"的覆盖度。
- 比 130×130 更小的图（如 64×64 图标）仍无法单遍完成。**可选 Stage 2**：
  源重流多遍（scaler 在源结束后请求 loader 重读同一文件，跳过已输出的行），
  最多 6 遍可覆盖到约 32×32。若时间不足，允许不做，但必须在报告中写明当前下限。

## 5. 任务 C：显示安全区（修掉上板裁切问题）

### C.1 诊断结论

显示器"自动"模式按 4:3 正确显示，但带 3~5% 过扫描。当前 OSD 几乎无安全边距：
顶部条从 `y=0` 起、参数面板右边界 `x=632`（右边距 1.25%），因此被裁切。

**目标显示设备是用户自带的 16 英寸 2560×1440/2560×1600 级别 144Hz 便携屏**
（评委不提供显示设备，演示用这块屏）。这类高分屏对 640×480 输入必须自行上采样，
其缩放器普遍带过扫描和图像增强，所以安全区不是可选项而是必需项。
输出像素时钟实测为 **25.000 MHz**（标准 VGA 为 25.175 MHz），
实际刷新率约 **59.52 Hz**，在显示器容差内，但过扫描行为必须以实测为准。

### C.2 安全矩形

```verilog
localparam SAFE_MARGIN_X = 32;   // 水平安全边距，5% of 640
localparam SAFE_MARGIN_Y = 24;   // 垂直安全边距，5% of 480
// 安全区：x ∈ [32, 607]，y ∈ [24, 455]
```

- `SAFE_MARGIN_X/Y` 必须是**参数**，便于按实测过扫描量调整。
- **顶部标题栏**：`TOP_BAR_Y0` 由 `0` 改为 `24`（`y = 24..48`）。
- **参数面板**：整体移入安全区，右边界 `x ≤ 607`。
- **滚动字幕与底栏**：`TICKER_BAR_Y = 432`、`BOTTOM_BAR_Y = 456` 保持不变
  （底部边距 24px = 5%，且音频柱几何已验证，不要动）。
- **音频柱**：几何**不改**（`x=224..415`、基线 `y=416`、白线 `y=415/416`、
  最高 `y=336`），全部已在安全区内。

### C.3 边缘测试图案（用于量化过扫描）

新增一个诊断图案（可挂在现有 `video_slide_diagnostic_pattern.v` 同一机制下，
或作为 fallback/诊断模式之一），用于测量显示器到底切掉多少：

- 在有效区最外圈画 **1px 白色边框**（`x=0/639`、`y=0/479`）；
- 在四边内侧按 1%、2%、3%、5%、8%、10% 位置画**刻度标记**（不同颜色便于区分）；
- 在安全矩形 `[32,607]×[24,455]` 边界画 **1px 青色边框**；
- 中心画十字线。

上板后切到该图案，记录哪一档刻度是可见的最外圈，即可读出实际过扫描比例，
据此调整 `SAFE_MARGIN_X/Y`。把实测结果写进报告。

## 7. 任务 E：重采样模式做成编译期参数（用于产出质量证据）

## 10. 非目标

- 不改 HDMI 输出时序（保持 640×480@60Hz）。**不要**尝试切到 800×480 或 720p——
  那会牵动 PLL、SDRAM 带宽、全部 OSD 坐标、缩放器目标尺寸和音频 ACR，
  属于独立决策，本次不做。演示用显示设备由用户自带（16 英寸 2560×1600 便携屏），
  640×480 4:3 信号按高度适配后显示为 **2133×1600**，即占屏宽 83.3%、占屏高 100%，
  左右各 213 px 黑边，属于正常的 4:3 呈现，无需改输出时序。
  （2560×1600 输出在本平台不可能：帧缓存需 8.19M 字 > SDRAM 2.1M 字，
  带宽需 246M 字/s > 125M 字/s，像素时钟需 268.5 MHz 而视频域 Fmax 仅 34.9 MHz。）
- 不追求全工程时序收敛。
- 不实现双三次/Lanczos（4 行行缓存已被 4 抽头面积滤波占满，且 LUT 余量不足）。
- 不改音频通路、频谱柱几何、转场特效、字幕内容。
- 不把生成的 bit 当作上板验收；**Flash 固化与断电冷启动验收由用户单独执行**
  （赛题硬性要求：最终设计必须固化在板上、上电即可运行）。
