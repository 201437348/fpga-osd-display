# HDMI 显示比例与图片等比例缩放：实施 Prompt

请在 `fpga/osd_display` 工程中完成一次“显示画布与图片缩放解耦”的改造。目标是：16:10 便携屏上画面尽可能占满，图片保持原始宽高比，必要时只留下可解释的黑边，不能出现 FPGA 黑边叠加显示器裁切，也不能因为显示器的宽屏模式把图片再次拉伸。

## 一、先确认问题边界

1. 当前输出时序是 640×480@60 Hz，画布比例 4:3；显示器“宽屏”模式会把整个 4:3 信号拉伸，显示器“自动”模式会按比例显示但可能产生左右黑边。
2. 图片缩放不能继续固定把所有源图映射成 640×480；必须先计算统一比例：

```text
s   = min(DST_W / srcW, DST_H / srcH)
ow  = floor(srcW * s)
oh  = floor(srcH * s)
x0  = (DST_W - ow) / 2
y0  = (DST_H - oh) / 2
```

图像区域外输出纯黑，图像区域内按 `(srcW,srcH)` 与 `(ow,oh)` 的比例映射采样。禁止 X、Y 使用两个独立的铺满比例。

## 二、实施顺序

### 阶段 A：先建立显示时序基线

1. 保留现有 640×480 构建作为回退配置。
2. 新增可选的 800×480@60 Hz 配置，优先复用工程已有的 `VIDEO_800_480` 时序参数；不要直接假设显示器支持 1280×800，也不要为了本任务新增复杂 PLL。
3. 将 `DST_W/DST_H`、OSD 坐标边界、行缓冲容量、帧 FIFO 的尺寸全部从单一硬编码改为同一组编译期参数。
4. 先输出纯色、边框和棋盘格诊断图，确认 800×480 信号能稳定锁定，确认有效区没有左右/上下被截断，再接入图片链路。
5. HDMI 输出时序、像素时钟、PLL、总线位宽和存储器时钟必须在报告中逐项列出；若 800×480 在目标屏上无法锁定，保留 640×480 回退，不得破坏原配置。

### 阶段 B：实现统一比例缩放

1. 在 loader 输出的真实 `srcW/srcH` 基础上计算 `s、ow、oh、x0、y0`，使用足够宽的无符号中间量，禁止 32 位乘法溢出和有符号截断。
2. 同时支持放大和缩小。缩小时至少使用正确的多抽头/面积平均策略；若资源不足，必须给出实际抽头数、画质影响和 LUT/BRAM/DSP 报告，不能把“2 抽头双线性”宣称成抗混叠滤波。
3. 采样坐标按像素中心对齐，避免整体半像素偏移。`X/Y` 落在 `[x0,x0+ow)`、`[y0,y0+oh)` 外时输出 `24'h000000`。
4. 让黑边只由 FPGA 产生一次。显示器设置使用“自动/原始比例/Just Scan/点对点”中的等比例模式，禁止使用“宽屏拉伸”。
5. 所有标题栏、参数面板、滚动条和音频柱必须放进可配置安全区；安全区不能改变图片的几何比例，也不能用裁切来解决越界。

## 三、必须验证的画面

在 800×480 目标画布下至少验证：

| 源图 | 期望结果 |
|---|---|
| 640×480 | 640×480 居中，左右少量黑边 |
| 1920×1080 | 800×450 居中，上下各 15 px 黑边 |
| 1920×1200 | 768×480 居中，左右各 16 px 黑边 |
| 1280×720 | 800×450 居中，上下各 15 px 黑边 |
| 320×240 | 640×480 居中，左右各 80 px 黑边（或按设计的放大上限） |

测试必须同时检查：

- 纯色四边框没有被裁切；
- 圆形/正方形仍为圆形/正方形；
- 黑边位置和宽度与整数计算一致；
- 640×480 回退配置仍能编译、仿真和上板；
- 不出现 FIFO 溢出、欠载、跨时钟域告警和时序恶化；
- OSD 文本在安全区内完整可见。

## 四、交付要求

请先给出“当前 640×480 链路的时序、画布、缩放器、OSD 坐标”的代码定位和修改清单，再逐步修改。每完成一个阶段都运行对应仿真并报告结果。最终报告必须分别说明：

1. HDMI 输出画布比例；
2. 图片实际显示矩形和黑边计算；
3. 显示器端推荐模式；
4. 资源与时序变化；
5. 800×480 不兼容时的 640×480 回退方式。

不要把“显示器拉伸/过扫描”当成图片缩放器问题，也不要在没有验证输出时序的情况下继续优化插值算法。
