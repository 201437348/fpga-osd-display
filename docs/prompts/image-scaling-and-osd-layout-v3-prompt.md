## 1. 现状与问题（已实测，作为设计输入）

### 1.1 缩放器对常见分辨率实际上不插值

`rtl/image/image_bilinear_scaler.v` 用 `STEP = floor(srcW·2^F/dstW)`、`fx = fix & (2^F-1)`
做定点步进。当 `srcW·1024/800` 是 1024 的整数倍时 `fx ≡ 0`，插值项恒为零，
输出退化为纯点采样。以 `dstW = 800` 重算：

| 源分辨率 | X 插值 | Y 插值 | 实际抽样 |
| --- | --- | --- | --- |
| 1600×960 | **失效(0% 像素)** | **失效(0%)** | 双向纯点采样 |
| 1600×1000 | **失效(0%)** | 激活 | 水平纯点采样 |
| 800×600 | **失效(0%)** | 激活 | 水平纯点采样 |
| 1920×1080 | 激活（800/1920 非整数比） | 激活 | 正常插值 |

> 表中只列**合法**源尺寸。`MAX_SRC_HEIGHT = 1080`，高度 > 1080 的图
> （如 1600×1200、1920×1200）会被 loader 直接拒收，不能作为测试样例。

规律：`srcW ∈ {800,1600,...}`（`srcW·1024/800` 为 1024 整数倍）或
`srcH ∈ {480,960}` 时该方向插值失效。
**注意：切到 800 宽之后失效点整体平移了**（640 时代的 640/1280/1920 变成 800/1600），
修复时必须以 `DST_WIDTH` 参数化判断，不能再硬编码 640。

### 1.2 2 抽头双线性本身不抗混叠

缩小时 2 抽头双线性是"重建滤波器"，不是"抗混叠预滤波器"：1920→800 每个输出像素
只读 2 个源像素，理想面积滤波应平均约 2.4 个。这是"鼓励优化缩放质量"要解决的问题。

### 1.3 宽高比处理：**有骨架，但常量停留在 640 画布时代**（已核实）

> **勘误**：本文档早期版本曾写"没有居中、没有黑边"，**那是错的**。
> `image_bilinear_scaler.v` **确实实现了** fit 矩形 + 黑边。下面是核实后的准确描述。

**已存在的部分**（骨架是对的）：

```verilog
reg [15:0] fit_w, fit_h, fit_x0, fit_y0;                          // L118
wire bar_pixel = (out_x < fit_x0) || (out_x >= fit_x0 + fit_w) ||
                 (out_y < fit_y0) || (out_y >= fit_y0 + fit_h);   // L334-335
```

**问题在于它不是通用公式，而是按宽高比分类的硬编码查表**：
L128-143 用移位/加法把源分成 5 档（只用移位加法、不用组合除法器，这一点设计得对），
L536-541 给每档写死一个 fit 矩形。

**当前 fit 矩形 vs 800×480 画布下的正确值**：

| 分类 | 当前 fit 矩形（代码） | 800×480 下应为 | 结果 |
| --- | --- | --- | --- |
| 16:9 | `800×360 @ (0,60)` | `800×450 @ (0,15)` | ❌ 横向多拉 25% |
| 16:10 | `800×400 @ (0,40)` | `800×480 @ (0,0)` | ❌ 横向多拉 25% |
| 3:2 | `800×426 @ (0,27)` | `720×480 @ (40,0)` | ❌ 横向多拉 25% |
| 4:3 | `800×480 @ (0,0)` | `640×480 @ (80,0)` | ❌ **铺满→拉伸 25%** |
| 窄于 4:3 | `360×480 @ (140,0)` | `360×480 @ (220,0)` | ❌ 尺寸对、**位置偏左 80px** |
| 其它比例 | `800×480 @ (0,0)` | 按 `s = min()` 计算 | ❌ 兜底铺满→拉伸 |

**根因（关键）**：这套常量是**为 640×480（4:3）画布写死的，且当时完全正确** ——
4:3 画布上 4:3 图正好铺满、16:9 图正好 640×360。画布切到 800×480 后：

- `fit_w` 写的是 `DST_WIDTH`，**跟着自动变成了 800**；
- `fit_h` 写的是字面量 `16'd360 / 16'd400 / 16'd426`，**没跟着变**；
- `fit_x0` / `fit_y0` 写的是字面量 `0 / 60 / 40 / 27 / 140`，**也没跟着变**。

于是所有横向档位都变成"宽度按 800、高度按 640 时代"，**系统性横向拉伸 1.25 倍**
（800/640 = 1.25）。同样地 `div_divisor` 的 fit 分支（L546-547、L581）也沿用了这些旧常量。

**4:3 档为什么直接铺满**：`aspect_43` 分支写的是
`fit_w <= DST_WIDTH; fit_h <= DST_HEIGHT; fit_x0 <= 0; fit_y0 <= 0;`
—— 语义就是"铺满整个画布"。这在 4:3 画布上正确，在 16:10 画布上就是**拉伸**。
**这就是 4 张官方 640×480 图变形的直接原因。**

**上板可复现的现象（用户实测）**：TF 卡放 4 张官方 640×480 + 1 张 1920×1080。

| 图片 | 命中分类 | 当前实际显示 | 正确应为 | 形变 |
| --- | --- | --- | --- | --- |
| 官方 640×480 | 4:3 | 800×480 铺满，无黑边 | 640×480 + 左右各 80px 黑边 | 横向拉伸 25%，一眼可见 |
| 1920×1080 | 16:9 | 800×360 + 上下各 60px 黑边 | 800×450 + 上下各 15px 黑边 | **同样横向拉伸 25%** |

> **为什么第五张"看起来"保比例**：它命中 16:9 档、**有黑边**，视觉上像"做了 letterbox"，
> 但 fit 高度是 360 而非 450，**实际同样被横向拉伸了 25%**。
> 想立刻验证：放一张 **1000×1000（1:1）** 的图，它会落进"其它比例"兜底档，
> 直接铺满 800×480，和官方图一样明显变形。
> （**不要用 1600×1200** —— 它高度 1200 > `MAX_SRC_HEIGHT = 1080`，会被直接拒收。）

**结论：宽高比功能"有骨架、常量全错、覆盖不全"。本任务要做的是**：

1. **用通用公式 `s = min(DST_W/srcW, DST_H/srcH)` 替换整张硬编码查表**
   （含 L536-541 与 L546-547、L581 的 fit 分支）；
2. 覆盖**任意**比例，取消"其它比例→铺满"的兜底拉伸；
3. **所有常量必须由 `DST_WIDTH`/`DST_HEIGHT` 推导**，
   禁止再出现与画布尺寸绑定的字面量（`360 / 400 / 426 / 60 / 40 / 27 / 140`）。
4. 建议保留"只用移位/加法分类"的低成本风格，但分类结果只能用来**选择抽头策略**，
   **不能用来决定 fit 矩形**——fit 矩形必须由公式算。

官方叫"自适应"，且框图里"缩放比"是单数，必须按**保持宽高比**实现。

## 3. 任务 A：图片缩放 v3（核心）

### A.1 修复目标与实现思路（本任务核心）

> 本任务是**用公式替换查表**：删除 §1.3 表格里那 5 档硬编码 fit 矩形，
> 改为由 `DST_WIDTH`/`DST_HEIGHT` 推导的通用公式。
> `fit_w/fit_h/fit_x0/fit_y0` 四个寄存器**可以保留**，但必须由公式驱动。

#### A.1.1 修复目标（可验收）

| # | 目标 | 判据 |
| --- | --- | --- |
| **G1** | 任意合法源都按**统一比例**缩放 | 对全部 `(srcW,srcH)`（1..1920 × 1..1080）抽样，`ow/oh` 与 `srcW/srcH` 的偏差只来自 `floor`，即 ≤ 1 像素 |
| **G2** | 图像**居中** | `xoff == (DST_W − ow) >> 1` 且 `yoff == (DST_H − oh) >> 1` |
| **G3** | 图像外输出**纯黑** | `bar_pixel` 区域恒为 `24'h000000`，且不消耗源数据 |
| **G4** | **无画布尺寸字面量** | 源码中不再出现 `360 / 400 / 426 / 60 / 40 / 27 / 140` 这类与画布绑定的常量；改画布尺寸后无需改缩放器 |
| **G5** | 恒等与铺满边界正确 | `srcW==DST_W && srcH==DST_H` → 逐位相同；`srcW/srcH == DST_W/DST_H` → 铺满且无黑边 |
| **G6** | 资源与时序不退化 | LUT ≤ 19000、BRAM ≤ 64、DSP ≤ 29、PLL = 2；SWNS ≥ −6.565 ns |

#### A.1.2 实现思路

**关键简化：统一比例意味着 X、Y 共用一个缩放因子**，因此**现有那个"配置阶段跑两次"的共享串行除法器仍然够用，不需要新增除法器**。

```
① 判定受限方向 —— 纯比较，不用除法
   width_limited = (srcW · DST_H <= srcH · DST_W)
   量级：srcW·DST_H ≤ 1920·480 = 921600   (20 bit)
         srcH·DST_W ≤ 1080·800 = 864000   (20 bit)
   → 20 位无符号交叉相乘比较即可，无需除法

② 受限方向直接铺满，另一方向用一次除法
   width_limited  → ow = DST_W,  oh = srcH · DST_W / srcW
   height_limited → oh = DST_H,  ow = srcW · DST_H / srcH
   （复用共享串行除法器：dividend = srcN·DST_M，divisor = srcM）

③ 居中偏移（纯移位）
   xoff = (DST_W - ow) >> 1
   yoff = (DST_H - oh) >> 1

④ 步进 —— 沿用现有两次除法，只把 divisor 从查表值改成 ow / oh
   step_x = srcW · 2^F / ow
   step_y = srcH · 2^F / oh
   因 ow/oh 保比例，step_x ≈ step_y（这就是"统一比例"的直接体现）
```

**改动清单（行号对应 §1.3 核实的现状）**：

| 位置 | 现状 | 改为 |
| --- | --- | --- |
| `image_bilinear_scaler.v` L536-541 | 5 档 `if (aspect_*)` 写死 fit 矩形 | **删除**，换成 ①②③ 的公式计算 |
| L546-547 | `div_divisor` 的 fit 分支（含字面量 `16'd360`） | 统一用 `ow` |
| L581 | `div_divisor <= fit_h` | 改为 `oh` |
| L466 | 复位初值 `fit_w<=DST_WIDTH; fit_h<=DST_HEIGHT; ...` | **保留**（作为合法初值） |
| L128-143 | 宽高比分类（移位/加法） | 可保留，但**只能用于选择抽头策略，不得再决定 fit 矩形** |

**开销**：除法器运行次数从 2 次变 3 次（多一次算非受限方向尺寸）。配置阶段每张图只跑一次、
每次 `DIVW = 27` 拍，**总开销可忽略**，不影响 §A.5 的吞吐约束。

**必须注意的几点**：

- **不会越界**：`s = min(...)` 的定义保证 `ow ≤ DST_W`、`oh ≤ DST_H`。
  放大时（`s > 1`）是"受限方向铺满"，另一方向数学上也不会超过画布——
  例：height-limited 时 `s = DST_H/srcH ≤ DST_W/srcW`，故 `ow = srcW·DST_H/srcH ≤ DST_W`。
- **除零**：`srcW`/`srcH` 为 0 已由 `cfg_w_valid`/`cfg_h_valid`（L125-126）拦住；
  仍需保证 `ow ≥ 1`、`oh ≥ 1` 再进除法器。
- **位宽**：`srcW·DST_H ≤ 921600`（20 bit），现有 `DIVW = 27` 足够，无需加宽。
- **floor 一致性**：`ow`/`oh` 与 `step_x`/`step_y` 必须用同一套取整规则，
  否则会出现半像素漂移。§A.3 的半像素偏置要与此一起改。

#### A.1.3 几何公式

```
DST_W = 800, DST_H = 480
s    = min(DST_W / srcW, DST_H / srcH)          // 统一缩放比，Q16 定点
ow   = floor(srcW * s)                           // 图像显示宽，<= 800
oh   = floor(srcH * s)                           // 图像显示高，<= 480
xoff = (DST_W - ow) >> 1                         // 水平居中偏移
yoff = (DST_H - oh) >> 1                         // 垂直居中偏移
黑边 RGB = 24'h000000
```

- `s` 用 Q16（16 位小数）表示，配置阶段用现有共享串行除法器计算，**不新增除法器**。
  若 LUT 紧张可用 `s = min(floor(800·2^16/srcW), floor(480·2^16/srcH))` 的保守下取整。
- **放大与缩小都要支持**：`s > 1` 放大（小图铺满），`s < 1` 缩小（大图适配）。
- 输出坐标 `(X, Y)` 到源坐标的映射：
  - 若 `X < xoff` 或 `X >= xoff+ow` 或 `Y < yoff` 或 `Y >= yoff+oh` → 输出黑边；
  - 否则 `sx = (X - xoff) · srcW / ow`，`sy = (Y - yoff) · srcH / oh`（定点，同现有机制）。
- **实测样例（按 DST = 800×480 重算，必须与实现一致）**：

### A.2 面积平均抗混叠滤波（本次核心得分点）

- **抽头数上界**（`MAX_SRC_WIDTH=1920`、`MAX_SRC_HEIGHT=1080`、DST=800×480）：
  - 宽度受限时（`s = 800/srcW`）：`r_x = srcW/800 ≤ 1920/800 = 2.4`
  - 高度受限时（`s = 480/srcH`）：`r_x = srcH/480 ≤ 1080/480 = 2.25`
  - 故 `r_x, r_y ≤ 2.4` → `taps = ceil(r) + 1 ≤ 4`，**两个方向都不超过 4 抽头**。
- **权重定义**（对输出像素 i，源方向步长 r）：
  足迹 `[i·r, (i+1)·r)`；源像素 k 的贡献 = 重叠长度
  `w_k = max(0, min((i+1)·r, k+1) − max(i·r, k))`；权重和恒为 `r`，归一化到 `2^F`。
  用定点实现，保证 `Σw_k = 2^F` 精确无偏（不能有累积误差）。
- **退化情形**：
  - `r ≤ 1`（放大）→ 用 2 抽头双线性（面积滤波在放大时退化为双线性，无需 4 抽头）。
  - `r` 为整数 → 权重为均匀 `1/r`，等价于 `r` 抽头箱式平均。
- **禁止**：不得为了省逻辑而回退成 2 抽头"近似"——那正是要修的问题。

### A.3 半像素中心对齐

现有 `sx0 = floor(i·srcW/DST_W)` 采样点落在源像素**左边缘**，正确位置是
`(i+0.5)·srcW/DST_W − 0.5`。修正：累加器初值加偏置 `(STEP − 2^F)/2`，
使采样点落在像素中心。放大时此项影响明显，必须修。

### A.4 行缓存改造（BRAM 不增加）

- 现状：8 个 `lbuf_1024x24`（4 槽 × 2 半行），容量 2 行 × 2048 px，占 24 个 BRAM9K。
- 目标：**4 行 × 1920 px**（垂直 4 抽头所需），`1920×24 = 46080 bit`，
  每行约 6 个 BRAM9K → 4 行约 24 个 BRAM9K，**与原占用持平**。
- 寻址按 `MAX_SRC_WIDTH ≤ 1920` 重新推导，删除"半行"概念或保留但重算槽位映射。
- 若 4 行排布导致 BRAM 超限，允许降级为 **3 行 + 3 抽头垂直**，
  但必须在报告中明确说明并给出质量对比数据。

### A.5 吞吐约束（必须守住 7 拍/输出像素）

- 现有输出回路 `EM_P0..EM_P6` = 7 拍/像素。
- 源流速率由 SPI 决定：spi_clk = 100MHz/((0+2)×2) = 25MHz，
  每源像素 3 字节 = 24 bit = **96 拍 @100MHz**。
- **4 个抽头必须并行**（新增约 3 个 8×11 乘法器），不得串行展开成更多拍。
  若必须串行，则重新推导 §A.6 的最小尺寸判据并如实报告。
- DSP 只剩 3 个，新增乘法器**优先用 LUT 实现**，不得让 DSP 超过 29。

### A.6 最小源尺寸判据（改为周期数比较）

- 原理：黑边不需要源数据，可以在源流结束后输出；**只有图像区域必须在源流结束前产出**。
  故约束为 `ow·oh·7 ≤ srcW·srcH·96`（与画布尺寸无关）。
- 代入 `ow·oh = srcW·srcH·s²` 得 `s² ≤ 96/7 = 13.71` → **`s ≤ 3.70`**。
- **用周期数比较替换现有的 `MIN_SRC_PIXELS = 32000`**（`fat32_bmp_loader.v` 的
  `src_pixels_ok`，已核实当前仍是 32000）：接受条件改为
  `(ow * oh * 7) <= (srcW * srcH * 96)`，全部用 32 位显式补零运算避免截断。
- 效果：最小可用尺寸从 32000 px 放宽到约 **130×130**（正方形源、s≈3.70）。
- 比 130×130 更小的图（如 64×64 图标）仍无法单遍完成。**可选 Stage 2**：
  源重流多遍（scaler 在源结束后请求 loader 重读同一文件，跳过已输出的行），
  最多 6 遍可覆盖到约 32×32。若时间不足，允许不做，但必须在报告中写明当前下限。
